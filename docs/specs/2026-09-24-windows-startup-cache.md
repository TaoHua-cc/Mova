# Windows 启动缓存分层

## 基本信息

- 标题：Windows 启动缓存分层与旧数据迁移
- 日期：2026-09-24
- 状态：Windows 实现完成，滚动渲染继续跟踪
- 影响平台：Windows；Android 保持现有存储路径

## 背景与问题

Windows `shared_preferences.json` 在当前用户数据中约 10.4 MB、922 项。插件首次读取时解析整份 JSON，且每次写入都会重写整份文件。TMDB 响应、排期和详情资源快照占文件的大部分；启动门等待偏好加载，因此缓存越多，进入首页越慢。后台刷新写入大文件也可能阻塞界面。

## 目标

- 保留已有用户列表、设置、观看记录和缓存内容。
- Windows 启动偏好文件不再随元数据缓存增长。
- 榜单继续先显示本机数据，过期后后台刷新；断网仍可显示缓存。
- 缓存写入不再重写全部设置。
- 建立可重复的启动与帧耗时验收。

## 非目标

- 本次不重做页面动画和图像缓存策略；这些需要独立帧采样验证。
- 不改服务端协议、榜单有效期和用户设置格式。

## 用户流程与界面

新安装直接读取内置首次列表快照；已有安装在首次新版启动时迁移大缓存，品牌启动画面保持响应，之后进入原有列表。后续启动只读取轻量偏好和需要显示的独立缓存。后台更新失败时保留旧内容。迁移失败时回退旧偏好缓存读取，不丢用户数据。

## 数据与接口

- Windows 独立缓存：TMDB 响应及刷新时间、TVmaze 排期、详情资源快照。
- 旧键：`yingji.tmdb.cache.*`、`yingji.schedule.*`、`yingji.detail.res.v1.*`。
- 每项独立文件，文件名由稳定摘要生成，文件内容保留原键与值以验证一致性。
- 缓存文件写入完成后才从旧偏好文件移除对应键；迁移中断可重试。
- 播放地址和请求头只保存在用户本机应用数据目录，不写日志，不打包进软件。

## 技术方案

- 在启动偏好实例初始化前，对 Windows 旧偏好文件做一次后台隔离解析与迁移；完成缓存落盘后一次性缩小偏好文件。
- 新增单项文件缓存，TMDB、排期和详情缓存读写走该层；非 Windows 保持原路径。
- 清理、统计和容量修剪覆盖新缓存。
- 使用现有 `FrameTrace` 测 Windows 发布构建的首屏与滚动帧耗时。

## 兼容与迁移

- 旧版本数据继续可读；迁移失败保留旧文件并回退旧路径。
- 迁移重复执行安全；缓存文件损坏时走旧值或网络恢复。
- 回滚到旧版本后，新版本写入的缓存不会被旧版本读取，但用户设置、列表和观看记录仍可读取。

- `dart format`、`flutter analyze`、`flutter test`、Windows release 构建。
- 测试纯迁移规则、单项缓存读写与中断重试。

## 风险与回滚

- 首次升级仍需处理一次旧文件，品牌画面可能短暂显示；迁移放在后台隔离运行以维持动画响应。
- 缓存文件属于可恢复数据；旧数据只在所有写入成功后移除。若磁盘空间不足，保留旧偏好数据并继续原路径。

## 实现记录

当前本机旧偏好文件从 10,834,931 B 缩到 271,458 B；迁出 TMDB 160 项、排期 36 项、详情快照 31 项，原用户设置仍在。首次迁移约 1.0 秒；后续启动迁移检查约 17 ms、偏好就绪约 24 ms。启动动画固定等待从 720 ms 缩至 250 ms；最终发布构建的壳层就绪约 253 ms、发现布局约 311 ms、首页轮播缓存约 335 ms。以上是一次本机样本，不是跨设备 p95。

存储优化不能解决发现页全部问题：同机 1264×681、170 Hz、自动滚动样本的深处 raster p95 仍约 23–30 ms，且关闭全部玻璃仍有显著绘制成本。缩小海报解码尺寸、增大图片内存上限、去除一层栏目 RepaintBoundary 均无稳定收益，已撤回。滚动时的后台元数据发布改为停稳后合并应用，避免滚动期重建，但并未宣称帧率目标达成。下一阶段需固定已加载栏目集合，使用 Flutter Profile timeline 定位具体绘制层，再在保留视觉效果的前提下减少每帧合成工作。
