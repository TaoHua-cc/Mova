# Android 发现页海报快照缓存与首页轮播手势

## 基本信息

- 标题：Android 发现页海报快照缓存与首页轮播手势
- 日期：2026-10-01
- 状态：已完成（Windows 人工回归未单独执行）
- 影响平台：Android 与 Windows（Windows 保持原行为）
- 关联 Issue、提交或版本：无

## 背景与问题

- Android 首页大海报只有左右边缘轻点与轮播圆点可切换，没有触控滑动。
- 海报图片字节有 `CachedNetworkImage` / `DefaultCacheManager` 缓存；发现栏目数据也有 TMDB 响应缓存，但 Android 没有复用 Windows 的栏目快照层，冷启动时无法先展示上次渲染的真实栏目数据。
- 榜单请求已有八小时缓存刷新间隔。快照用于稳定冷启动首屏，不替代 TMDB 的缓存与刷新策略。

## 目标

- Android 首页大海报增加水平滑动，保留点击详情、圆点、左右点击和纵向页面滚动。
- Android 发现页持久化真实栏目快照，冷启动先恢复上次展示的栏目数据，再由既有 TMDB 逻辑按其刷新间隔更新。
- 记录上一轮平板滚动优化的实际效果和原因，不宣称整个应用已完全流畅。

## 非目标

- 不冻结 TMDB 内容或伪造数据；上游缓存过期并成功刷新后栏目允许更新。
- 不改自动轮播间隔、玻璃效果、Windows 输入行为或图片字节缓存策略。
- 不持久化首页当前轮播选中索引；用户反馈的问题是发现栏目海报数据快照。

## 数据与兼容

- Android 快照存于应用支持目录 `metadata-cache-v1/discover`，以栏目、来源、筛选组合为 key 的 SHA-256 文件名；每份最多 20 条，最多保留 96 份。
- Windows 继续通过原有 `WindowsMetadataCache` 文件格式与路径读写。
- 旧版本没有 Android 栏目快照时沿用原 TMDB 响应缓存/网络加载，不需要迁移；TMDB 榜单原八小时刷新间隔不变。

## 实现记录

- Android 已扩展发现栏目快照到应用支持目录；Windows 继续使用既有文件缓存。快照保存真实栏目数据，榜单缓存新鲜度仍由 TMDB 请求层控制（默认榜单 8 小时）。
- 已移除误解需求新增的首页轮播选中项偏好键；首页水平滑动手势保留。
- OPD2401 本地测试包上，发现栏重启前后的可见栏目和海报一致；没有通过无障碍树检查文件命中，但设备日志未见 Flutter 异常。
