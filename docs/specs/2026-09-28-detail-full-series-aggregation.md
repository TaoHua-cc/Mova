# 详情页完整剧集聚合与可恢复超时

- 日期：2026-09-28
- 状态：已完成
- 影响平台：Windows、Android

## 背景与目标

单个服务器连接超时会中断整部剧的聚合并将原始异常显示给用户；长剧的剧集接口只取前 200 条，详情缓存又只保留前 800 条。季集切换及手动重新搜索应始终对应当前作品的完整服务器资源。

## 用户流程与界面

打开详情页先显示已缓存资源；首次或手动重新搜索遍历当前作品在所有已连接服务器上的匹配结果。切换季集后资源列表仅显示对应剧集的可播放版本。单个服务器失败时保留其他服务器结果，显示简洁失败提示并允许重新搜索。宽窄屏沿用现有资源区布局，鼠标与触控均使用现有按钮。

## 数据与接口

- 不新增持久化键或服务端协议。Emby/Jellyfin 剧集接口按 `StartIndex` 翻页，直到结果完整。
- 旧缓存格式继续读取；后续完整扫描覆盖旧版截断的快照。
- 服务器错误不显示原始异常详情或令牌。

## 验收标准

- [x] 超时服务器不会阻断其他服务器资源，失败可手动重试。
- [x] 超过 200 集的剧集可以完整取回，超过 800 行的缓存可以完整恢复。
- [x] 切换季集仅显示相应资源；重新搜索全剧且尽量保留当前选择。
- [x] Windows、Android 共用逻辑，无虚假剧集或播放资源。

## 验证计划

- [x] 剧集翻页和缓存回读的自动测试。
- [x] `dart format`、`flutter analyze`、相关 `flutter test`。
- [x] Windows 构建与本地部署；Android 共用代码由测试覆盖，设备人工验证待进行。

## 风险与回滚

完整长剧快照会占用更多本机存储。若服务器忽略翻页参数，检测重复页面并终止，避免无限请求。可回滚代码；旧缓存格式未变。

## 实现记录

增加全剧分页、仅按父剧集匹配、单服务器失败隔离、完整缓存和重搜时选择保留；直接从服务器剧集打开详情也会继续聚合整部剧。完整测试套件 208 项通过（最后一次小改动后针对性测试 11 项通过），静态检查无错误，Windows Release 已部署。Android 设备实测及真实《辛普森一家》服务器数据核对尚未执行。
