# Windows 发现栏目会话快照

## 基本信息

- 日期：2026-09-24
- 状态：Windows 实现完成；持续滚动光栅优化另行跟踪
- 影响平台：Windows；Android 保持现有加载方式

## 背景与问题

有保存过发现页栏目布局的用户，每次启动后 `_DiscoverPage` 先用 `sectionLimit=0` 建立空内容；滚动接近栏目才逐项从元数据缓存重建列表。即使榜单数据未过期，用户仍看见空列表变成海报。当前可见栏目扩展流程还会对与屏幕现有内容完全相同的结果再次预热图片，增加滚动期工作。

## 目标与非目标

- 启动恢复保存的栏目顺序时，同时优先恢复上次实际显示的真实榜单与海报信息；进入影视榜单完整列表也先显示上次结果。
- 后台刷新和榜单八小时规则不变；内容相同时不重新发布或预热。
- 不取消玻璃、背景动画、海报质量或栏目功能。
- 本项不宣称解决所有 raster 帧耗时；独立性能归因仍按 Windows 性能路线执行。

## 用户流程与界面

首次安装无快照时仍使用安装包内真实首装榜单；以后启动优先显示上次成功展示的榜单，离线时也能继续浏览。用户修改栏目来源或筛选条件后，新配置不复用旧来源的快照。快照损坏时回退既有缓存/网络路径；保存中的磁盘错误不阻断页面。

## 数据与接口

- 使用现有 `TmdbItem.toJson/fromJson` 和 `WindowsMetadataCache`，新增 `discover` 域的每栏目独立文件。
- 文件键由栏目标题、来源和筛选设置共同确定；布局样式不改变内容键。
- 只保存最多 20 个当前预览项；文件不含账号凭据或视频地址。
- 清理 TMDB 元数据缓存时同步清除发现栏目快照；旧文件无需迁移。

## 技术方案

新增小型快照编解码层；`_initializeSections` 在布局恢复后读取已保存栏目快照，首装内容仅补缺。完整影视榜单的四个来源同样先读快照，再静默刷新。页面已显示内容与新读取结果相同则跳过通知和图片预热。新结果成功发布后异步写快照，不让磁盘写入阻塞滚动。限制快照总数，防止用户多次改筛选造成无限积累。

## 兼容与迁移

- 旧版不读取新文件，原 TMDB 缓存、布局偏好和观看记录不变。
- 新版第一次打开若无快照，继续走旧数据路径；使用后逐渐生成快照。
- Android 不读写新域；回滚旧版安全，新域文件可作为可再生缓存清理。

## 验收标准

- [x] 已有快照的 Windows 再次启动，不等滚到栏目时才填充海报。
- [x] 完整影视榜单第二次打开无需等待四个来源请求全部完成。
- [x] 同内容刷新不触发栏目通知和额外图片预热。
- [x] 来源/筛选条件纳入快照键；坏快照的编解码回归通过。
- [x] 清理缓存与容量限制覆盖新域。
- [x] 全部测试、静态检查和 Windows 构建通过，部署本地。

## 验证计划

- 单元测试快照编解码、配置键隔离与坏数据回退。
- 现有发现页虚拟化测试继续通过；测试启动、滚动、筛选变化与缓存清理。
- Windows 宽窗/窄窗人工检查首装、已有数据、离线、上下往返滚动；比较同条件帧采样。

## 风险与回滚

风险是快照过期或筛选变化显示不相干内容；通过复合键及后台刷新处理。快照仅可再生元数据，出现问题可清理 `discover` 域并回到原加载路径。

## 实现记录

本机首轮往返滚动后生成 16 份栏目快照；第二次启动 `discover_snapshot_ready` 约 304ms。相同 1264×681、170Hz、9 秒往返路径的单次滚动采样由约 86fps/raster p95 25.72ms 到约 91fps/20.68ms，受首次加载与后台工作的差异影响，不应当作稳定的 A/B 性能提升。持续滚动的 raster 瓶颈仍在；还需要固定内容的多次 Profile 样本。首次升级若旧版没有会话快照，浏览到的栏目会逐步建立快照；从第二次启动起才享受完整恢复。

最终部署后的诊断采样（同一往返路径）为约 86fps、raster p95 21.12ms；仅诊断性关闭普通玻璃背板采样后约 89fps、raster p95 21.36ms。单次数据不足以判断小幅差异，但说明普通玻璃模糊不是此路径的主要瓶颈；不应为此牺牲用户要求的实时玻璃。持续滚动的光栅归因与视觉流畅性仍未达到验收目标。

海报显示宽 168px、榜单海报区 130px，旧实现均按 320px × DPR 解码。改为按实际展示宽度 × DPR 解码后，两次相同往返采样均约 94.9fps、raster p95 分别 19.94/18.40ms；此前保留 200/160px 余量的两次采样约 92fps、raster p95 24.26/20.70ms。卡片级 `RepaintBoundary` 实验两次只有 66.8/78.4fps，已撤销。实际展示尺寸方案保留；桌面截图检查海报与圆角未见明显质量下降。高刷新率持续滚动仍未达目标，不把这项局部收益称为完整解决。
