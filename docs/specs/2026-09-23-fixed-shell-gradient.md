## 基本信息

- 标题：固定渐变背景与首页海报分层
- 日期：2026-09-23
- 状态：调整流动方式中
- 影响平台：Windows、Android

## 背景与问题

当前壳层把首页轮播海报同时作为发现和其他页面的全屏背景，并叠加模糊副本。首页向下滚动会更新全屏遮罩。用户希望这些页面改用不随海报变化的固定多色渐变，以降低背景绘制开销。

## 目标

- 首页首屏继续展示真实轮播海报，底部渐变融入发现区域。
- 发现和其他壳层页面只显示固定多色渐变，不共享海报或模糊海报。
- 滚动不驱动全屏模糊计算；固定配色的渐变色层可缓慢流动，但不随海报或滚动位置改色。

## 非目标

- 不调整数据加载、榜单卡片构建或缓存协议；首次打开速度需测量，不宣称必然提升。

## 用户流程与界面

进入首页看到海报；向下滚动，海报随首屏离开，底部渐变与固定壳层渐变衔接。发现、搜索、追剧、片单、来源和设置页背景保持相同颜色，与当前海报无关。缺少海报时仍显示渐变。键盘、鼠标和触控不改变操作路径。

## 数据与接口

不新增数据来源、网络请求、持久化键或接口。保留已有轮播设置和真实海报数据。

## 技术方案

壳层背景不订阅轮播海报与滚动深度；使用宽于屏幕的多色线性渐变带沿对角方向缓慢平移。色带尺寸与亮度固定，颜色从屏幕边缘连续流入流出，不使用径向色斑产生呼吸/缩放错觉；静态绘制的色带仅更新合成位移，不增加图片解码或背景模糊。将轮播海报仅放进首页首屏 Sliver，以现有图片缓存和轮播转场设置渲染；在其底部用透明度渐变透出壳层背景。

## 兼容与迁移

Windows、Android 共用 Flutter 实现，无数据迁移；回滚安全。播放器视频背景不在本次范围；使用共用 `YingjiBackdrop` 的详情和独立列表页同步改用固定渐变。

## 验证计划

定向 Widget/源码约束测试、Flutter 静态检查、Windows 构建；Android SDK 可用时构建 APK。对比首屏与发现页滚动帧耗时，避免仅凭视觉宣称性能提升。

## 风险与回滚

固定渐变与部分海报的色温可能不一致，以较宽的深色底部渐变降低接缝。若视觉验收不达标，可只调整渐变颜色，不恢复全屏模糊海报。

## 实现记录

已将海报图层移入首页首屏 Sliver，共用背景改为两层宽于屏幕的线性渐变带，并以 28 秒周期沿相反方向缓慢平移。色带尺寸不变，不再产生径向色斑的呼吸/缩放错觉。背景不再用首页海报作为其他页面背景，也不再随滚动计算全屏模糊。未新增依赖、请求或持久化数据。

验证：定向测试通过；`flutter analyze --no-fatal-infos` 无错误或警告（18 条既存 info）；Windows Release 构建通过并部署至 `D:\Mova\mova.exe`。完整测试 127 通过、1 项既存的发现栏目断言失败（`test/widget_test.dart:163`）。Android 构建因本机无 SDK 未运行。

Windows 宽屏实测时发现海报暗色遮罩没有跟随海报一起渐隐，首屏与发现页存在水平色带；已修正、重新构建部署并复查，色带明显收敛。追剧页已确认使用固定渐变而非首页海报。

Profile 采样（1264×681、170Hz、8 秒滚动）滚动阶段约 130fps；进入发现页前两秒 `raster_p95` 约 17.8ms，仍有掉帧。跳过全部玻璃层的单次对照结果受启动/加载波动影响更差，不能据此归因。跳过首页海报图层的采样仍约 133fps、前两秒 `raster_p95` 约 17.0ms，说明该图层不是剩余卡顿的主要来源。尝试缩小发现海报解码尺寸仅带来约 1–2fps 的单次差异，已撤回，避免牺牲清晰度。没有同条件旧版本基线，因此不宣称已量化性能提升；首次打开时间、窄屏和 Android 仍需进一步验证。

流动色彩追加验证（2026-09-23）：`test/flowing_backdrop_test.dart` 与发现滚动定向测试均通过；静态检查无错误/警告，18 条既有 info。Windows Profile 1264×681、170Hz 往返滚动采样约 96fps，内容加载状态不同，不能与前次样本做严格因果比较；流动色层本身持续合成，有 GPU 成本。Windows Release 已部署到 `D:\Mova\mova.exe`。实际窗口已查看首页向下进入发现区域，蓝、紫、青色背景清楚可见，未见黑灰底。Android 实机与窄屏仍未测。
