# Mova 播放器控件与弹幕体验

## 基本信息

- 标题：播放器图标区分、二级菜单对比度与弹幕绘制效率
- 日期：2026-09-23
- 状态：实现中（待实机视觉复核）
- 影响平台：Windows

## 背景与问题

Windows 原生播放器工具栏的剧集、字幕、弹幕图标外观容易混淆；视频画面较亮时，低浓度白色玻璃上的白色菜单文字与图标对比度不足；弹幕帧绘制还会无条件执行只用于诊断的逐轨重叠检测。

## 目标

- 让 Windows 原生播放器的剧集、字幕、弹幕入口使用语义明显不同的图标。
- 所有播放器二级菜单在亮/暗画面上都保持清晰，同时仍通过实时背板模糊呈现玻璃材质；选中态采用克制烟棕/古铜，不使用蓝色或粉色。
- 剧集缓存图片晚到后可热更新原生面板，避免因起播等待超时而永久显示占位图。
- 默认播放时跳过仅供诊断的弹幕重叠扫描；开启诊断时保留完整指标。

## 非目标

- 不新增图标依赖，不改变弹幕 API、缓存或偏好键。
- 不改动播放器解码、缓冲和视频刷新策略。

## 用户流程与界面

- Windows 原生工具条与面板使用同一语义图标。
- 工具、音轨/字幕、倍速、画面、弹幕、章节、剧集、资源、片头片尾及“更多”入口展开的二级菜单共用珍珠烟棕色实时磨砂材质，文字与图标用深色，选中/焦点使用低饱和古铜色；不以透明白字覆盖浅色影片。
- 菜单保持键盘焦点、Escape 关闭和鼠标滚动可用。
- 弹幕只在诊断环境变量开启时计算逐轨重叠指标；正常播放路径不承担该扫描成本。

## 数据与接口

- 图片仍由应用侧使用既有缓存获取；新增仅限 Windows 播放会话内的 `MOVA_PLAYLIST_IMAGE=<index>|<path>` 本机 stdin 消息，不变更网络协议、持久化键或缓存格式。

## 技术方案

- 复用 Windows 原生播放器的 Iconsax 字体码点、玻璃背板采样/模糊和 GDI+ 面板组件。
- 逐轨重叠诊断的预扫与区间碰撞检测受 `MOVA_TRACE_DANMAKU` 开关控制；正常播放仍保留弹幕轨道布局和贴图绘制。
- 参考 `apple/DESIGN.md` 的低噪声层级、材质与工具控件尺寸，同时遵循 `DESIGN.md` 的播放器平台边界；选中色遵循用户反馈回归棕色，不采用蓝色或粉色。
- 启动只查询已有图片缓存；缺失图在播放器启动后后台获取，完成时经本地 stdin 通知原生窗口更新对应集缩略图。

## 兼容与迁移

- Windows 控件由原生 C++ 绘制；Android 不在本次范围内。
- 无缓存、协议或持久化迁移；回滚安全。

## 验收标准

- [ ] 剧集图片在冷缓存和已有缓存两种情况下都能显示；冷缓存图片到达后无需重开面板即可出现。
- [ ] 二级菜单配色为克制烟棕/古铜，不出现玫瑰粉或蓝色强调。
- [ ] 剧集（视频播放）、字幕（字幕框）、弹幕（多消息气泡）图标形态明显区分。
- [ ] 播放器二级菜单在明亮与暗色影片背景上文字、图标、边缘均清晰且背板仍实时模糊。
- [ ] 弹幕动画仍按屏幕刷新节奏更新；默认不执行诊断用逐轨碰撞扫描。
- [ ] 宽屏鼠标与键盘菜单操作正常。

## 风险与回滚

- 浅色玻璃会改变播放器菜单的原有深色观感；通过保留高模糊背板、圆角、玻璃折射和明确边线维持产品一致性。
- 弹幕流畅度变化应使用 `MOVA_TRACE_DANMAKU=1` 的帧间隔、绘制耗时和 DWM 节拍指标实测；本次优化仅移除正常路径的诊断扫描。

## 实现记录

- Windows 原生播放器工具图标已切换为 video_play / subtitle / message_text 字形；子菜单使用中性珍珠烟熏色实时模糊玻璃、深色墨色文字与柔和玫瑰珍珠选中状态。
- 根据后续反馈，二级菜单去除所有 Action Blue 残留，所有被选资源/选项统一玫瑰珍珠色；弹窗锚点空间预算包含投影边距，并在窗口移动时保留列表滚动位置且不抢焦点。
- 剧集列表没有单集剧照时，将真实剧集海报作为缓存备用图；冷缓存超时不再把空路径永久固定在原生启动参数里，图片到达后由本机会话消息热更新当前面板。
- 二级菜单选中态从玫瑰粉回归烟棕/古铜；玻璃背板和白色光学反射维持中性，避免整体染粉。
- 默认弹幕绘制跳过逐轨重叠诊断的预扫和碰撞比较；设置 `MOVA_TRACE_DANMAKU=1` 时仍运行并输出原有诊断数据。
- `mova_native_player` Release 构建成功，并将生成的 `MovaNativePlayer.exe` 更新到 `D:\Mova`；部署文件 SHA-256 与构建产物一致。
