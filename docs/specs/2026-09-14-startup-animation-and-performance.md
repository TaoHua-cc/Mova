# 启动动画与首帧性能优化

## 基本信息

- 标题：启动动画与首帧卡顿修复
- 日期：2026-09-14
- 状态：已完成
- 影响平台：Windows / Android

## 背景与问题

应用当前在 `runApp` 前等待桌面窗口显示、SharedPreferences 和代理设置加载。Windows 窗口已经可见但 Flutter 首帧尚未提交时，会表现为数秒空白或卡住。首页建立后还会启动真实数据加载，造成第二次明显停顿。

## 目标

- 尽早提交 Flutter 首帧并显示品牌启动动画。
- 将偏好和代理初始化合并为一次 SharedPreferences 读取。
- 窗口在首帧准备好后再显示，避免暴露未绘制画面。
- 初始化失败时使用安全默认值进入应用，不永久停在启动页。
- 启动完成后平滑过渡到真实首页。

## 非目标

- 不伪造加载百分比或虚假媒体数据。
- 不改变播放器初始化方式、用户设置格式或服务器协议。

## 用户流程与界面

启动后显示深色画布、Mova 图标、名称和真实的不确定进度动画。动画至少显示一个短周期以避免闪烁；设置加载完成后淡出并进入首页。窄屏与宽屏共享构图，按可用尺寸缩放。

## 数据与接口

- 继续读取既有 SharedPreferences 键。
- `ProxyRouting` 新增接收现有 SharedPreferences 实例的同步载入入口，`load()` 保持兼容。
- 不新增持久化字段和网络请求。

## 技术方案

- `main.dart` 创建启动 Future 后立即 `runApp`，并在首帧回调中显示桌面窗口。
- 新增独立 `MovaStartupGate`，负责启动动画、最短展示时间、异常兜底和内容切换。
- `YingjiApp` 接受可选启动 Future；Widget 测试未传入时直接显示应用，保持现有测试兼容。
- SharedPreferences 只获取一次，同时应用外观并灌入代理内存状态。

## 兼容与迁移

- 所有旧设置继续读取，不需要迁移。
- Windows 首帧后显示窗口；Android 沿用系统原生启动画面后进入 Flutter 动画。
- 回滚不影响任何用户数据。

## 风险与回滚

- 风险：过长的最短动画会增加可感知等待，因此限制为短周期。
- 监测方式：Widget 测试、首帧人工观察与 release 构建。
- 回滚：恢复 main 中同步初始化并移除启动门控，不涉及数据回滚。

## 实现记录

- `runApp` 现在不再等待 SharedPreferences 与代理状态；桌面窗口在 Flutter 首帧后显示。
- 启动阶段复用一个 SharedPreferences 实例，外观与代理状态在后台初始化。
- 新增 720ms 最短品牌动画和 360ms 淡入切换；动画完成后停止控制器，初始化异常自动进入首页。
- 启动专项测试 3 项全部通过；静态分析无错误（21 条既有 info）；Windows release 构建成功。
- 完整测试 59 项中 57 项通过。既有失败为 `HDR10+DV` 识别与发现栏目空态测试，均与本改动无关。
