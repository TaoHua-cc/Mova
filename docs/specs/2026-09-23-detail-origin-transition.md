## 基本信息

- 标题：详情页从内容卡位置展开
- 日期：2026-09-23
- 状态：已实现，待双端人工验收
- 影响平台：Windows、Android

## 背景与问题

详情页作为独立路由又绘制了一套左侧导航，与主界面侧栏重复。打开剧集时使用普通页面转场，看不出详情与刚点击的内容卡之间的关系。

## 目标

- 移除详情页左侧导航，保留顶部返回、搜索与桌面窗口按钮。
- 从内容卡所在位置展开详情页；返回时朝同一位置收合。页面正文保持原有统一左锚点。
- 对无法取得内容卡位置的入口使用普通淡入，保持可访问性与稳定性。

## 用户流程与界面

用户点击首页、发现页、搜索或列表中的作品卡片，详情页以该卡片的屏幕区域为起点展开。键盘与触控入口同样可进入详情；系统关闭动画设置时直接显示。顶部返回按钮或系统返回操作关闭详情页。

## 数据与接口

仅改变路由转场和页面布局，不新增持久化键、网络请求或业务数据。

## 技术方案

在详情页提供共用打开方法，从点击控件的 `RenderBox` 取得相对 Navigator 的矩形，并把卡片中心换算成页面缩放锚点。路由允许 Flutter 对转场内容快照，使用 GPU 缩放与淡入，避免逐帧重新裁剪、布局和绘制完整详情页。常见卡片入口统一使用该方法。删除详情页侧栏和它专用的布局补偿值；顶部及正文直接使用 `YingjiLayout.pageLeft`。

## 兼容与迁移

- 旧数据可继续读取，无迁移。
- Windows 和 Android 共用动画；桌面窗口按钮仍只在 Windows 出现。
- 回滚安全，无格式变化。

## 风险与回滚

来源控件离屏或已卸载时不能准确收合，路由应退回淡入淡出。可回滚到普通 `MaterialPageRoute`，不影响数据。

## 实现记录

已移除详情页专属侧栏，统一卡片入口的来源矩形转场，无法定位来源时淡入。窄屏操作区及资源栏改为自动换行。

后续性能复查将逐帧 `Rect.lerp + ClipRRect + FittedBox + Opacity` 改为允许快照的锚点 `ScaleTransition + FadeTransition`，进入 300ms、退出 240ms；仍从所点卡片方向展开/收合，但不再每帧重新布局整页。

播放器进入详情流程也增加转场：Android 播放页使用允许快照的轻微缩放淡入淡出，Windows 原生播放器窗口在系统动画开启时使用 Win32 淡入/淡出，系统关闭动画时直接显示/关闭。
