# 发现页滚动绘制隔离与优化

## 快照视觉回归修正与全程复测

整行快照会隔离标题操作玻璃的外部采样源，并按自身矩形截断允许溢出的横向货架。改为标题/操作区保持实时、仅货架内容快照；货架始终使用相同矩形裁切，避免快照开始/结束出现边界变化。首页大海报也使用滚动期间固定快照，外层透明度仍连续随深度变化，避免过渡中重复 ShaderMask/图片转场滤镜合成。按首页到末尾完整单向路径采样，不只选择稳定发现区。快照期间新加载图在停止时恢复显示的限制保持不变。

第一轮修正版全程 20 秒对照：标题保持实时后 raster P95 中位数从 5.73ms 回退为 11.05ms，未部署。进一步仅为同一标题栏中非重叠按钮加入 opt-in BackdropGroup，使用 BackdropFilter.grouped 合并相同玻璃采样；嵌套及其他玻璃不分组，防止重叠材质串色。共享代码 Android 构建验证，但短时快照仍只在 Windows 启用。

共享采样也未改善全程，已撤回，不保留分组组件。最终方案将发现页标题限定为既有 YingjiFixedGlass 固定雾面材质（停止/滚动均一致，不再实时采样画面），标题和货架分别短时缓存，避免跨越货架边界或透明采样；其他页面标题保持原材质。还修复平滑滚轮在 min/max 边界无位移时仍反复切换滚动状态、重新捕获快照的问题。新增边界滚轮、固定玻璃状态和快照布局回归测试。此处对“保持实时玻璃按钮”的初始方案作了明确调整：保留品牌高光、描边和外观浓度，但不承诺按钮采样真实背板。

最终增加发现区域暂停装饰背景漂移，回到首页首屏恢复。299 项测试通过，分析无错误/警告（19 项既有 info），双端 Release 构建通过。2026-10-02 已部署 Windows，构建/安装 app.so SHA256 一致：CE56BC4AD33D741142A08EA9CE988FE3DA258D07692C29B3F05B5083E2A29465。Android 未安装或真机测试，桌面视觉边界尚待用户实际窗口复核。

全程采样：1264×681，DPR 1，170Hz，6 秒后以 500px/s 输入驱动 20 秒直到底部。日志 build/feed-full-before.log、build/feed-full-final.log。对比 wall 7000–26050ms 的 20 个窗口：帧回调速率中位数 161→160，raster P95 中位数 5.73→6.05ms；全部窗口超预算帧 281/2641→761/3194，不能宣称整段性能全面改善。该段包含到达底部后采样驱动仍强制调度帧的区间。

严格取位置仍在移动（pos<max）的 12 个窗口：回调速率中位数 164→165，raster P95 中位数 5.73→5.71ms，超预算帧 224/1888→197/1931。首页过渡的一秒窗口回调速率 43→154，raster P95 10.27→9.31ms，仍超 5.88ms 预算，且单窗口数据不可作稳定 FPS 保证。停止驱动后最终只有 3 帧尾帧，之后无持续 FRAMES 输出；旧版仍持续输出约 106–130 帧/秒背景动画。快照首次生成、新栏目加载及过渡区仍有慢帧，未达到全程零掉帧。FrameTrace 的回调帧计数存在按批次交付，不等同于实际显示器呈现 FPS。此次未推送或发布。

## 证据与范围

Windows 170Hz（帧预算约 5.88ms）发现栏目纵向滚动：build P95 通常小于 2ms，raster P95 约 18–23ms。关闭玻璃、海报图片或卡片装饰单项不能恢复流畅；保持滚动几何但隐藏整行栏目后 raster P95 约 3.1–3.2ms。栅格缓存提示实验无明显改善，已撤回。

## 验证性方案

使用 Flutter 内置 SnapshotWidget 在 Windows 纵向滑行期间将栏目暂时显示为冻结纹理，停止立即释放并恢复实时绘制。横向货架滚动期间禁用快照，窗口尺寸变化自动更新；卸载释放控制器及监听。Android 不启用。图片/数据在冻结期间完成加载会在滑行结束显示，不改变数据缓存、来源请求或持久化设置。

先用相同 20 秒、700px/s 往返路径验证效果；无改善则撤回，不以构建成功代替性能验收。保留真实数据、玻璃外观、点击及悬浮操作。未授权 Git 推送或发版。
