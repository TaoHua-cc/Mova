# Windows 缓存流失败恢复

- 状态：实现中；2026-10-10；仅 Windows。
- 实测基线：下一集切到缓存桥后，在 32 MiB 补流处重复 HTTP 403；38.6/3052.1 秒提前 EOF，同桥重试仍失败。源站 403 的具体原因尚未确认。
- 目标：预加载不是播放失败单点；缓存流异常可在同窗口断点恢复正常取流。
- 方案：复用 MOVA_EPISODE_RESOLVED；每集自动恢复一次，用原始源 URL 重新开流，使源站重新处理重定向，不复用 prepared URL。直连服务器强制原生取流；勾选代理不绕过设置，保持既有代理路径。
- 不更换版本、不切引擎、不改观看状态格式、不关闭 TLS；不承诺断网或持续 403 时无停顿。预加载与 80% 规则保留。
- 验证：白名单协议、直连/代理路由、断点与有限恢复预算；构建后本地复现原切集场景；60 分钟长测未完成前不是上架合格。
- 回滚：撤销本次恢复协议，无数据迁移。Android 不部署。

## 实现与交付

- 已修改：缓存流提前结束时每集一次 MOVA_RECOVER 请求；沿用同 libmpv/窗口更新地址和原始鉴权，从断点开始。直连绕过预热 URL 与可选本地缓存；用户代理不绕过；恢复失败有操作提示。保存诊断和进度逻辑保留。
- 范围澄清：重新开原始源 URL 以触发新的重定向，不重新登录、不刷新媒体服务 API 凭据；长期失效凭据仍可能失败。尚未实现完整原生下一集预加载交接，也不声称实现无缝零停顿。代理服务器仍可能受到原桥补流问题影响，后续需独立验证。
- 已测试：路由、白名单、缓存补流、资源列表及退出进度共 18 项通过。原生恢复预算/断点协议目前为源码接线检查，不能代替实际故障注入。针对性 analyze 无 error/warning，2 处既有 info；diff check 通过。
- 已构建部署：Windows release 成功，用户正常退出后覆盖 D:/Mova，exe/app.so/libmpv 哈希一致；受校验 gpu-next DLL，保留数据。Android 不构建、不部署；未提交、推送或发布。
- 未完成：真实原场景复现、全量测试、60 分钟长测、持续 403 的媒体凭据刷新。当前仍有公开上架阻断项，不能称稳定性全部通过。
