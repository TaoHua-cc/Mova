# 日历：国内平台排期与卡片可读性

## 基本信息

- 标题：补齐日历中文标题、观看进度与国内平台排期
- 日期：2026-09-24
- 状态：已实现并部署 Windows；待用户用实际日历数据复核
- 影响平台：Windows / Android（共享业务逻辑）
- 关联 Issue、提交或版本：无

## 背景与问题

日历截图显示深色平台标识在海报背景上对比不足，待看条目以英文原名展示；进度条只在 Trakt ID 与进度数据都存在时渲染，未映射条目和本地观看记录没有进度展示。国内平台的 TMDB/Trakt 日期缺少集级时间，当前仅 TVmaze 可补部分时刻。

## 目标

- 显示 TMDB 简体中文剧名，并在多来源合并后保留中文标题。
- 深色平台标识在沉浸式海报上清晰可辨，不加实色 logo 底框。
- 本机观看记录与 Trakt 进度融合后显示已看/未看/总集，不重复累加同一集。
- 只从公开且可核验的排期源补真实播出时刻；不根据日常惯例推算或填造。

## 非目标

- 不接入需用户 Cookie、登录态、签名密钥或逆向破解的私有接口。
- 不改变播放记录、待看、Trakt 同步与既有缓存 schema。

## 用户流程与界面

日历卡片在宽/窄布局均优先显示中文主标题；平台 logo 视觉可读而无不透明底框；存在进度来源及总集数时呈现进度条。具体播出时间仅在上游明确发布时间时显示，来源缺失时保留“时刻未公布”。

## 数据与接口

- 输入与输出：TMDB 简体中文剧名、Trakt 进度、Mova 本地 WatchState、公开平台/聚合器集级发布时间。
- 数据来源：TMDB、TVmaze、Trakt，以及经核实的国内平台公开节目页/文档化端点。
- 新增/修改字段：只增加内存模型字段；持久化键、现有事件 JSON 向后兼容。
- 网络接口、超时与错误处理：使用项目已有代理 HTTP client、超时和缓存；单一平台失败不影响其它来源。
- 隐私与敏感信息：不收集或记录第三方平台 Cookie/令牌。

## 技术方案

- 复用 `TmdbClient.upcomingEpisodes` 返回的 TMDB 中文名称，向日历事件补充本地观看计数。
- 调整 `calendar_events.dart` 合并规则，避免英文 Trakt 标题覆盖 TMDB 中文名。
- 复用现有 `_CalendarPlatformLogo`；仅将识别为深色的图标渲染为高对比浅色，不引入底框。
- 评估并实现可公开核验的中国区排期来源；如果没有公开可用数据，不使用非公开接口或时间推断。

## 风险与回滚

- 主要风险：平台官网页面可能改版；平台排期可能只表达周更规律而非集级确认时间。
- 监测方式：保留严格解析和时间未知空态，接口异常不中断其它来源。
- 回滚步骤：撤回对应数据映射，旧缓存可继续读取。

## 实现记录

实现记录：TMDB Upcoming Episodes 现在带回 `zh-CN` 节目名；合并时防止英文源覆盖中文名。进度计数将本机已完成 WatchState 集数与 Trakt completed 取较大值（防重复），总数取本地播出源与 Trakt aired/已公布总集的较大值，未看为总数减已看；卡片现在展示进度标题、已看百分比及已看/未看/总集三组读数。HBO/Max/Apple TV 深色 logo 在卡片上以白色单色滤镜提高对比，不增加底色。

“择日飞升”之前没有具体时刻的原因是旧适配器抓取 `so.iqiyi.com` 的客户端渲染搜索壳层，并把它当成含剧名和排期的 HTML 解析；实际返回页没有节目条目，因而永远无法命中。现改为查询爱奇艺公开搜索 JSON `mesh.if.iqiyi.com/portal/lw/search/homePageV3`，只接受唯一精确标题，并解析公开 `updateTime`、`subscriptContent` 和 `totalNumber` 字段，生成下一集周六 09:00 的排期。结果缓存 6 小时，不保存整页 HTML，不携带登录 Cookie；平台搜索失败或内容不明确时仍显示“时刻未公布”。官网节目页也标注每周六 9:00：[择日飞升](https://www.iqiyi.com/a_26rzlsl1999.html)。其他国内平台仍需各自公开、可核验的数据适配器，未接入的平台不猜时间。Windows 已通过本地开发部署脚本安装至 `D:\Mova`；Android 共享逻辑未单独构建验证。
