# 下一集取流衔接与资源排序

- 日期：2026-10-09
- 状态：实现中
- 影响平台：Windows 取流诊断；双端资源排序

## 问题与目标

用户报告 Windows 自动跳到下一集后短暂播放，随后持续缓冲。检查预加载前缀与源站后续数据衔接，不能将前缀视为完整影片。播放器资源列表必须使用详情页当前的色彩范围/分辨率/码率/大小排序，切集后仍一致。

## 方案与兼容

复用现有缓存与原生播放器，不另建缓存机制。排序状态归详情页父状态管理，卡片、版本弹窗与播放器复用同一排序函数。保留 `yingji.detail.resource-sort` 键与现有缓存格式、服务器代理规则；无迁移。实际缓冲原因需要受控测试或播放证据，不以猜测代替结论。

## 验收与验证

- 四种排序下，详情页与播放器候选顺序一致；切集后的异步候选同样排序。
- 有预加载前缀时，后续取流完整且不永久停在缓冲；失败应有界恢复。
- 自动化：排序单测、缓存 HTTP/Range 衔接回归、静态检查、双端构建。
- 人工：Windows 连续自动切集三次，记录缓冲与恢复；双端核对排序。播放管线长测 60 分钟未执行前不宣称上架合格。
