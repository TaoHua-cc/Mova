# Android 启动与转场开销优化

- 日期：2026-10-01
- 状态：已实现，仍需完整路径性能复测
- 平台：Android；Windows 保留原转场与启动门控

## 目标与方案

Android 保留系统居中图标启动画面，初始化设置后直接进入首页，不再播放 Flutter 启动动画。
普通页面使用 Flutter 原生 Zoom 快照转场，避免对复杂页面逐帧重绘缩放与透明度。
详情页 Android 入口使用相同原生转场。播放器含原生视频视图，不能可靠快照，直接进入/退出。
Android 二级弹窗取消入场缩放/淡入，保留原玻璃模糊、触控和关闭行为。
不修改缓存、持久化键、数据接口、凭据或版本号；不修改既有弹幕修复。

## 验收与验证

定向测试检查 Android 转场选择、弹窗动画与 Windows 原行为。
Release AOT 构建并安装到平板，不清除数据；复核首页→完整列表→详情→返回及编排弹窗。
记录实测与未执行项，不将构建通过等同于帧率提升。Windows 不部署。

## 风险与回滚

系统启动图标可能等待设置初始化稍久；无额外最低等待时间。
快照转场期间异步图片更新在结束后显示；视频视图不做快照。
回滚仅恢复入口、转场和 dialogAnimationStyle 调用，无数据迁移。

## 实现记录

Android 主界面/完整列表与详情页使用原生快照转场；播放器零时长进入/退出。
21 处 Dialog、4 处详情底部面板和共用快捷菜单保留玻璃，但 Android 不做整体缩放/透明度动画。
启动跳过 Flutter 品牌画布，修正 bypass 时仍运行 pulse ticker 的问题。
5 项启动/Android 动效测试通过；相关静态检查无错误，3 项原有 info。
详情回归测试 11 项通过，1 项既有源码定位断言 RangeError（不涉及本次转场）失败。

平板 3000×2120 横屏 Release AOT：系统居中图标、首页→详情→返回、
发现→完整列表→详情→返回以及编排/全部剧集弹窗已操作验证，玻璃模糊保持。
初轮诊断包仍观察到 raster 最大 79.50ms，编排打开窗口 raster 平均 34.56ms；
这些窗口混合初始化/空闲，不能作为连续 FPS 或旧新版提升率。
随后修正 bypass ticker 并补上底部面板路径，日常包关闭诊断日志。
