# 滚动、排序与窗口状态回归修复

## 基本信息

- 标题：滚动/拖动交互与最大化状态同步
- 日期：2026-09-23
- 状态：已完成
- 影响平台：Windows
- 关联 Issue、提交或版本：无

## 背景与问题

发现页栏目编排弹窗未使用共享桌面平滑滚轮处理器，滚动仍是离散跳格。首页悬浮标题栏的最大化图标和提示为固定值，最大化后仍显示“最大化”。通用窗口控件在窗口状态读取重叠时可能丢失最后一次刷新。

## 目标

- 发现页栏目编排列表沿用共享平滑滚轮和静态玻璃滚动策略。
- Windows 鼠标仍可直接拖动排序。
- 首页最大化/还原图标和提示反映窗口实际状态，并在并发状态刷新时最终收敛。
- 设置中的播放器工具重排保留现有 Windows 拖动操作。

## 非目标

- 不改榜单、发现数据加载策略或持久化结构。
- 不改变 Windows 窗口尺寸/最大化行为本身。
- 不触碰与本次交互无关的已有工作区改动。

## 用户流程与界面

- Windows：滚动发现栏目编排列表时连续平滑移动；鼠标可直接拖动排序；最大化后按钮变为还原图标且 Tooltip 显示“还原”。
- Windows：设置页工具排序保留即时鼠标拖动；窄窗口布局与键盘操作保持原有行为。

## 数据与接口

- 无数据/协议/持久化变化。
- 窗口状态继续从 `WindowHost` 查询真实最大化与全屏状态。

## 技术方案

- 发现栏目排序弹窗使用 `YingjiSmoothWheel`、独立 `ScrollController` 与 `yingjiWheelPhysics`。
- 首页复用 `YingjiWindowControls`；当异步状态读取期间又收到刷新信号时，完成当前查询后排队再读一次。
- 保留现有排序监听器行为，不改变触控端或 Android 交互。

## 兼容与迁移

- 共享 UI 代码中只启用 Windows 桌面滚轮拦截；未改 Android 行为。
- 无持久化迁移；回滚安全。

## 风险与回滚

- 风险：用户侧最大化状态事件在边界竞态下依赖最后一次窗口查询收敛。
- 回滚：撤销本规格对应的组件包装与拖动监听变更即可。

## 实现记录

- 首页复用通用窗口状态控件；最大化同步若有并发查询，会在本次查询完成后再刷新。
- 编排弹窗接入共享桌面滚轮；保留鼠标拖动排序逻辑和 Android 原行为。
- 首页滚动背景采用与详情页相同的 1/24 量化深度曲线。
- 发现入口等待栏目偏好恢复及布局完成后再执行滚动；原测试调整为推进有限帧，避免持续背景 ticker 使 `pumpAndSettle` 永远无法结束。
- 珍珠色断言改为匹配实际使用的半透明色值，保留玻璃透底效果。
- 完整 Flutter 测试 143 项通过；定向测试、Windows Release 构建通过；analyze 通过（18 条 info 级提示）。
