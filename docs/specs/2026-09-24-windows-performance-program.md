# Mova Windows 产品架构、体验与性能路线

## 基本信息

- 日期：2026-09-24
- 状态：持续执行；第一阶段已落地
- 影响平台：Windows

## 产品目标

安装后第一次打开就能看到软件携带的真实发现栏目与海报；后续打开立即恢复用户自己的首页、列表和继续观看。网络数据静默更新，不阻断浏览。功能、资料与缓存增长不应线性增加启动耗时。桌面滚动、转场和播放器需要分别按发布构建实测，而不是以动画时长或主观观感代替帧率。

Mova 按长期维护的完整桌面软件建设：允许安装包包含必要字体、首装内容、播放器组件与诊断资源，不以缩小体积为目标；已确认的清透玻璃、流动背景、海报清晰度和功能入口属于体验约束。性能改进优先消除重复工作、阻塞与错误的职责边界，不以默认关闭效果、减少功能或降低画质作为交付结果。

## 全局设计原则

- **先可用，再更新**：首页、继续观看和发现栏目优先读取持久快照；刷新、评分、扩展详情和非首屏海报在后台按可见范围与优先级执行。过期缓存可显示并标注状态；无缓存时呈现真实空态，不用假内容。
- **交互状态稳定**：页面切换保留滚动位置和焦点；鼠标悬停、滚轮起停、窗口缩放与弹层打开都不触发无关卡片重建或几何跳变。键盘、鼠标、窄窗和触控共享同一语义，呈现可以不同。
- **视觉效果有预算**：玻璃、流动渐变和转场保留，但每层需明确更新频率、作用区域与缓存边界。静态内容不能随背景动画重绘；昂贵效果由发布构建的 Profile 数据决定实现，而非猜测。
- **播放状态只有一个真相**：Windows 的 libmpv 是位置、缓冲、轨道与错误的权威来源，界面和观看记录反映其事件；网络重试、跳转进度和弹幕加载不得分别猜测播放成功。
- **可扩展但不提前空转**：新功能按领域入口接入既有缓存、来源、播放和视觉组件；当现有边界妨碍性能或正确性时再拆模块。避免把新逻辑继续堆入 `media_center.dart`、详情页或原生播放器主文件。

## 现有架构与优先边界

目前 `lib/src/media_center.dart` 约 1.5 万行，详情页约 5.7 千行，Windows 原生播放器主文件约 7.8 千行；这是维护和局部性能定位风险，不等于文件长本身会拖慢运行。按以下边界渐进重构，不做一次性技术栈迁移：

1. **应用壳与导航**：窗口、主题、路由和页面生命周期留在壳层；首页数据请求、发现栏目编辑、服务器管理和设置各自拥有状态，避免全局通知让无关页面重建。
2. **数据与离线层**：小偏好、观看状态、可再生元数据、海报/图片、视频缓存分别管理。统一请求去重、并发上限、取消/过期策略、来源状态和容量清理；优先复用现有客户端与缓存实现。
3. **渲染层**：明确首屏、滚动视口、卡片、背景、弹层的绘制边界；只预取即将可见的资源。统一玻璃和交互令牌，不在各页面复制近似组件。
4. **播放层**：Windows 原生播放器保持独立进程；播放命令、mpv 事件、网络 Range 代理、弹幕与观看记录分别可观测。Android 共享业务规则，但本轮性能实施范围仅 Windows。
5. **发布与诊断**：安装包携带首装快照和必需播放器组件；升级保留用户资料。开发版可采集启动阶段、请求数、帧耗时、内存/缓存体积和播放器故障阶段；生产日志不包含凭据或播放地址。

## 开源项目参考边界

- [Jellyfin Desktop](https://github.com/jellyfin/jellyfin-desktop)：借鉴桌面播放器与本机配置/缓存/日志分层、安装版与便携版交付思路；不为此改用 Qt WebEngine。
- [ImPlay](https://github.com/tsl0922/ImPlay)：借鉴 mpv 能力的可发现入口、快捷操作、章节/轨道等播放工具组织；不复制其 UI 或脚本架构。
- [Moonlight PC](https://github.com/moonlight-stream/moonlight-qt)：借鉴硬件能力检测、Windows 打包和高帧率体验的验证纪律；它的串流协议与 Mova 的媒体资料库不是同一问题。
- [Flutter 性能指南](https://docs.flutter.dev/perf/ui-performance)：使用 Profile 模式分别判断 UI 与 raster 线程，避免把 60/170 Hz 的帧预算和动画主观观感混为一谈。

参考仅用于设计决策；如将来复用第三方代码或资源，先单独核对许可证与归属。

## 当前基线

- 当前用户 Windows 偏好文件原为 10.8 MB / 918 项；第一阶段迁移后约 271 KB，TMDB / 排期 / 详情缓存共 227 个独立文件。
- 迁移后正常启动：本机 1264×681、170 Hz，偏好就绪约 24 ms；缩短固定动画后，壳层就绪约 253 ms，首页轮播缓存约 335 ms（单次发布构建样本）。
- 自动发现页滚动深处仍有约 23–30 ms 的 raster p95。关闭玻璃后仍有大量内容绘制成本，单靠减模糊无法达到高刷目标。

## 阶段与工程约束

1. **启动与存储（已实现）**：小型设置与可重建大缓存分离；旧用户一次性迁移；独立文件按需读取；失败回退；内置首装内容继续可用。下一步补断网和全新安装实机验证。
2. **绘制归因**：建立固定的已加载栏目与固定滚动路径，采集 Flutter Profile timeline、UI/raster p50/p95/p99、纹理上传与 layer 数；重复 5 次取中位数。同一窗口尺寸、显示刷新率、缓存状态与栏目集合，才比较代码改动。记录可见卡片类型，定位具体昂贵层。
3. **发现页渲染**：只对归因确认的热点改动。优先考虑减少透明叠层、过度裁切和重复图层，或把静态卡片合成结果缓存；保持已有液态玻璃、海报清晰度、悬停展开和固定渐变流动视觉。每项改动做 A/B，没收益即撤回。
4. **数据与扩展（进行中）**：各功能模块按进入页面初始化；首屏只预取海报与继续观看，后续栏目按可见范围、后台优先级与并发上限准备。Windows 过期 TMDB 缓存的后台刷新已加全进程同键去重和 3 个并发槽；无缓存的前台请求仍不排队，Android 路径不变。下一步分别测请求数、图片预热、失败退避、磁盘缓存容量与版本清理，避免功能变多后旧缓存无限增长。账号数据与可重建公开元数据分开存放。
5. **播放器与安装交付**：继续把 libmpv 原生播放器放在独立进程，播放卡顿按解码、网络、弹幕与帧节奏分别测；安装包必须携带首装快照、海报和受校验的 gpu-next libmpv，升级不得覆盖用户资料。正式发版仍按 `RELEASE.md` 的签名与发布流程执行。

## 验收门槛

- 指定 Windows 测试机：本机缓存首页在冷启动后目标 1 秒内可操作；断网启动不转全屏等待；首次升级允许一次后台迁移，但界面保持响应。
- 60 Hz 下连续滚动帧的 p95 总耗时目标 ≤16.7 ms、无 >100 ms 停顿；高刷屏另记录 90/120/170 Hz 实际帧节奏，不把 60 FPS 冒充满刷新。
- 至少测：全新安装、旧数据升级、热启动、断网、缓存损坏、18 栏滚动往返、完整榜单、详情进入退出与播放器跳转。
- 新功能合入前比较启动时间、内存峰值、磁盘缓存大小、请求数及帧耗时；若回退超过既定门槛，先修性能再扩功能。
- 首页、发现、完整榜单、详情和播放器分别检查加载、空数据、断网、失败恢复、返回后位置保持与键盘操作；不能只通过首页截图认定整体体验完成。
- UI 优化在亮/暗海报、宽/窄窗口和高 DPI 下检查文字、玻璃层、焦点、海报边缘与转场；性能版本不得默默降级视觉令牌。
- 每个大阶段交付可单独回退的 Windows 本地版本及前后同条件采样；达不到收益的试验撤回，不累积开关和未证实的补丁。

## 当前风险

现有 170 Hz 设备的发现页仍有光栅瓶颈。仅凭本次存储迁移不能宣称已达到大型客户端的整体流畅度；第二阶段需按 Profile trace 作出可验证的渲染取舍。

## 本轮实现记录

- Windows 已有缓存的 TMDB 后台刷新改成全进程按缓存键去重、最多 3 个并行请求，防止过期榜单同时刷新时重复网络、解析和写盘；缓存仍即时返回，前台缺缓存请求不受限制。
- 增加并发/去重回归测试；这项措施控制后台峰值，不宣称已修复发现页持续滚动的 raster 瓶颈。
