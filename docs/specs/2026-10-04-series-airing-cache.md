# 播出安排持久化、Trakt 时间优先与完结标记

- 日期：2026-10-04；状态：已实现并双端本地部署，真实数据人工验收待完成；影响：Windows / Android 共享日历与详情。
- 基线：详情 NextEpisodeLabel 每次挂载调用 upcomingEpisode；底层分别缓存响应，但无作品级播出结果。日历合并先遇到具体时间就保留，Trakt 时刻不一定优先；无完结标签。
- 目标：复用现有元数据/播出缓存，作品级结果持久化；6小时内反复进入不重复联网；下一集播出后刷新失效的下一集结果。连接 Trakt 时优先精确时刻，失败保留其他来源，日期未知时不编造小时。
- 判定：明确 ended/series_finale 或 TMDB ended 且最终集真实播出，显示已完结；不以无下一集、总集数或观看完成度单独判定。日历只在对应末集的卡片显示。
- UI：沿用字体、固定玻璃、信息行；日历季集行附加已完结，详情更新时间区域显示已完结。宽窄布局保留截断和来源提示。
- 数据：新增播出结果缓存键（作品ID+是否连接Trakt），内含保存时间、下一集列表、最终季集号、完成状态；不存凭据。日历事件新增可选source/seriesFinale，缺字段兼容旧数据。旧海报/详情缓存不删除。
- 接口：Trakt按TMDB ID精确解析作品，再读公开next_episode/last_episode，使用既有客户端与超时、鉴权刷新；TMDB/TVmaze作为回退。遵守官方UTC时间换算，不对未知时间造值。
- 验收：首次查询后重进和重启缓存命中；连接状态隔离；Trakt时刻优先且中文片名/平台logo保持；末集并集卡片显示完结，非末集/仍在更新不误报；断网旧数据仍可展示。
- 验证计划：mock网络与偏好缓存测试，事件合并/完结边界测试，双端构建和保留数据部署。真实资源日历日期/详情标签、离线重进、窄屏与触控待实测；不涉及播放管线，不宣称正式上架验收。
- 回退：旧版忽略新字段/新键，无破坏性迁移；缓存过期会重新查询，服务端未知/错误数据无法保证被自动校正。
