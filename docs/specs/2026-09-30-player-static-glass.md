# 播放器静态玻璃统一设计

- 日期：2026-09-30
- 状态：设计草案，尚未实施
- 影响平台：Windows 播放器；Android 视觉对齐需单独核验
- 关联：`docs/design/player-static-glass/`

## 背景与问题

当前播放器提示、控件与二级菜单的材质来源不同。Windows 控件与菜单存在实时背板采样绘制路径，而提示有独立固定材质；用户观察到模糊强度跳变、提示截断、快速操作时闪烁和视频卡顿风险。

## 目标

- 一套共享静态玻璃材质覆盖播放器控件、提示和二级菜单。
- 沿用全局外观模糊设置，但播放器 UI 不实时采样/模糊视频背景。
- 提供可编辑且可一比一复刻的设计图及尺寸、材质、动效和状态文件。

## 非目标

- 本次设计交付不直接改播放器运行时代码、不部署、不修改播放或缓存行为。
- 不新增生产演示数据、持久化键或服务端接口。

## 用户流程与界面

用户进入播放页，顶部信息、底部进度和分组控件稳定显示；调节操作在画面中部显示轻量提示；功能菜单自对应控制岛上方展开。键鼠、触控板与窄屏分别按 `implementation.md` 的几何和焦点约束适配。失败提示保留重试操作，空菜单显示真实状态。

## 数据与接口

输入仍来自当前媒体、libmpv、真实来源及既有外观设置；不增字段、持久化键、网络接口或敏感信息。

## 技术方案

以 `implementation.md` 为可执行设计规范。Windows 原生绘制统一静态渐变、固定高光和边缘；删除播放器 UI 的实时背板依赖。使用既有 `g_glass_blur` 映射强度。Android 沿用已有品牌/动效系统并检查视觉一致性，不强行复用 Windows 原生代码。

## 兼容与迁移

旧数据可继续读取；无需迁移。回滚只回滚 UI 绘制。设计文件不影响运行时。

## 验收标准

- [ ] 三类 UI 共用同一材质，无逐帧背板抓取
- [ ] 快速操作提示不截断、不抖动
- [ ] 全局外观设置 0/20/40 联动正确
- [ ] 亮暗画面、窄屏、键鼠和触控板通过验证
- [ ] 无虚假生产数据、无敏感信息泄露
- [ ] Android 预期差异已核验并记录

## 验证计划

设计阶段：检查 `preview.html`、`tokens.css`、底图和规范文件齐全，核对画板尺寸及状态覆盖。实施阶段：格式化、Windows C++ 编译、相关 Flutter 静态检查和测试；人工验证播放器持续播放帧率、菜单开闭、快捷键、亮暗画面和 0/20/40 外观设置。

## 风险与回滚

主要风险是固定材质在极亮画面上对比不足，及 C++ 材质合并时引入帧循环重绘。使用最小 alpha 下限、亮暗画面检查及帧时间采样；出现回归时回滚绘制函数，不涉及数据迁移。
