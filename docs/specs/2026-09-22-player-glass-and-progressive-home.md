# 播放器实时玻璃与首页渐进加载

## 基本信息

- 日期：2026-09-22
- 状态：已实现，待实机视觉验收
- 影响平台：Windows 播放器；Windows / Android 共享首页

## 背景与问题

Windows 播放器目前在 UI 线程每 160ms 截取一次窗口并进行 CPU 模糊，菜单背景只有约
6 FPS，且会阻塞控件动画。GDI+ 的细圆形描边经 DPI 与透明分层窗口合成后会出现锯齿。
首页虽然延迟挂载发现页，但随后仍批量请求多个栏目和预热大量图片；轮播首次网络请求
未完成时，整个首页画布也被加载指示器替代。

## 目标

- 播放器背景采集不再阻塞 UI，并以连续帧更新玻璃内容。
- 圆形按钮不再依赖容易产生锯齿的细描边。
- 首页首帧立即显示可用的本地内容，发现栏目仅在用户向下浏览时分批加载。
- 控制 SharedPreferences 中元数据缓存规模，降低后续冷启动解析成本。

## 非目标

- 不修改媒体协议、播放记录格式或用户设置键。
- 不伪造首启时尚未取得的海报或榜单。

## 技术方案

- 原生播放器用后台线程持续更新现有背板双缓冲；UI 线程只读取最新完成帧。
- 玻璃轮廓依靠抗锯齿形状边缘和光学层，不再绘制额外 1px 圆周线。
- 首页未取得轮播数据时仍构建电影画布和本地继续观看；发现区由滚动触发挂载，并按
  接近底部的距离增加加载栏目数。
- 发现区仅在滚动停止 180ms 后追加两个栏目；已有缓存内容在后台刷新期间保持挂载，
  刷新只重读当前已显示栏目并逐栏合并。每栏只预热首屏 6 张海报，避免批量解码抢帧。
- TMDB SharedPreferences 缓存上限收紧，并在本次运行首次写入后执行修剪。
- 榜单类 TMDB 请求采用严格 8 小时最短刷新间隔；有缓存时窗口内完全不发请求。
- 首页内嵌发现区移除 shrinkWrap 嵌套列表与无意义的透明度动画，每个栏目用独立
  RepaintBoundary 隔离绘制，减少纵向滚动时的重复布局和重绘。
- 发现页排序拖拽复用原卡片，不再由默认代理添加黑色 Material 阴影；完整榜单页
  接入共享的桌面平滑滚轮，并在移动端继续使用原生触控滚动。

## 兼容与迁移

- 旧缓存仍可读取；只淘汰可重新获取的旧元数据，不影响设置与观看记录。
- Android 不运行 Windows 原生采集线程，但共享首页渐进加载行为。
- 回滚安全，不需要数据迁移。

## 实施与验证记录

- 原生玻璃背板改为工作线程双缓冲，目标采样间隔 16ms；模糊降采样改为 1/6，工作线程仅休眠 1ms，界面线程只在新帧完成后刷新可见窗口。
- 屏幕区域采集不能可靠排除自身浮层，已改回播放器 HWND 专属 `PrintWindow` 视频源，再裁切玻璃区域；GDI 操作后刷新批处理，避免覆盖 CPU 模糊结果。
- 首页首屏只发起轮播与继续观看必要工作；发现区由滚动触发，并保留旧“发现”导航请求的兼容路径。
- TMDB 持久化缓存上限从 800 降为 160，每次运行首次写入即修剪旧项。
- `flutter analyze --no-fatal-infos --no-fatal-warnings`：通过（仅 18 条既有 info）。
- `flutter test`：96 项全部通过。
- MSVC `/W4 /WX /std:c++17 /utf-8 /O2`：通过，零警告。
- Windows Release 构建成功，已部署至 `D:\Mova\mova.exe`，并安装经校验的 gpu-next/libplacebo `libmpv-2.dll`。

## 本次玻璃纠正与实机验证

- 背板改用纹理填充抗锯齿路径，恢复单层细边，去除播放键外圈光晕及悬浮内圈。
- 调整 GDI+ 合成方式，降低菜单行白色叠层，避免低透明度叠加仍严重发白。
- 实机检查 1920×1160 播放器：暂停时新开菜单能取到背景，播放时菜单随窗格与场景色彩更新，没有观察到此前持续累积的白色残影。
- 16ms 仅为请求间隔；本机采集记录约 22–39ms，尚未达到稳定 60 FPS。GPU 共享纹理实时模糊尚未实现，不能宣称已完成。
- 本次未完成 Android、窄窗口及所有主应用页面的视觉回归。

## 风险与回滚

- 视频源采集依赖 Windows 窗口合成结果；受保护视频或驱动无法返回视频帧时，
  仍应退回透明材质。
- 后台采集必须在 GDI+ 关闭前停止并回收，避免退出崩溃。
