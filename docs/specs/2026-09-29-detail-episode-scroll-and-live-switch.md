# 详情页剧集浏览与 Windows 无缝切集

- 日期：2026-09-29
- 状态：实现中
- 影响平台：详情页两端；原生无缝切集为 Windows

## 背景与问题

TMDB 目录版“全部剧集”对话框未接入共享鼠标滚轮平滑组件；全部剧集条目的简介截断后不能悬浮查看全文。Windows 原生播放遇到未聚合条目时会关闭原生窗口，把季集号交给 Flutter 搜索，再重新启动播放器。

## 目标

- 全部剧集目录弹窗的鼠标滚轮继续使用 `YingjiSmoothWheel`，触控仍使用系统滚动。
- 剧集的选中/悬浮白框不包住简介；简介保持截断，并可通过鼠标悬浮读取全文。
- Windows 未聚合剧集搜索期间保留播放器窗口与当前画面；命中后由原生播放器直接加载解析出的地址，失败则继续当前播放。
- 快速切集时丢弃过期的异步搜索结果。

## 非目标

- 不更改资源聚合规则、媒体源优先级、观看记录格式、字幕/弹幕持久化。
- Android 播放器不改为原生播放；继续使用 Flutter 页面内切集。

## 技术方案

- 目录弹窗复用 `YingjiSmoothWheel` 与本地 `ScrollController`。
- 将目录行的白框限制在剧照/标题/集信息主体区域，简介另列并复用 `YingjiGlassTooltip`。
- Windows 沿用已有 stdout/ststdin 协议和窗口消息线程：未聚合选择时原生暂停并通知 Flutter；Flutter 按现有单集聚合回调搜索，命中后把播放地址、该项 HTTP headers 与续播点经 stdin 返回；窗口主线程在同一进程中更新条目并 `loadfile replace`。旧调用方或没有解析回调时保留旧的关闭/回传兼容路径。
- 搜索代次令牌丢弃过期响应；未命中时清除等待状态、恢复当前集。

## 兼容与迁移

- 无持久化、缓存格式或服务端协议变化。
- Windows / Android 差异：只有 Windows 原生进程使用动态地址热切换；Android 保持现有页面内切集。
- 不需要迁移，旧播放器调用方保留原有窗口回传行为。

## 验收标准

- [x] TMDB 与服务器资源两类全部剧集列表可用平滑滚轮滚动；触控滚动保持正常。
- [x] 剧集主体白框与简介分离；简介截断显示，悬浮可读全文。
- [x] Windows 搜索中播放器窗口不关闭；命中后同窗加载目标集并应用目标集续播点及 headers。
- [x] 搜索无结果/失败时继续当前集；快速切集时过期命中不能覆盖最新选择。
- [x] 不引入虚假资源或破坏观看记录。

## 风险与回滚

- 主要风险：stdin 动态响应与快速连续切集竞争；通过请求代次和目标索引校验避免过期加载。
- 回滚只需还原详情页组件与 Windows 原生播放器改动，无数据迁移。

## 实现记录

已实现。详情目录弹窗接入共享滚轮平滑控件，所有集列表的白框仅包住剧照和集信息，简介单独截断并通过 `YingjiGlassTooltip` 展示全文。Windows 原生播放器增加动态集解析通路：搜索态在顶栏标题反馈；命中同窗 `loadfile replace`，未命中恢复当前播放和标题；响应索引校验拦截过期结果。为避免提示浮层在动态切集退出时触发 GDI+ 收尾访问冲突，这条流程只更新顶栏文字，不复用 toast。

验证：Windows Release 构建通过；episode-switch 探针 05（命中）与 06（未命中）均通过，进程正常退出；Dart 静态分析/格式化结果见交付说明。Android 窄屏人工触控验证尚未执行。
