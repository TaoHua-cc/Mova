# 切集历史完成状态与下一集缓存预热

## 基本信息

- 标题：切集历史完成状态与下一集缓存预热
- 日期：2026-09-16
- 状态：实现中
- 影响平台：Windows / Android
- 关联 Issue、提交或版本：v3.1.104 后续开发

## 背景与问题

播放器已有下一集预加载设置，但 Flutter 播放页只发出一次临时 Range 请求，响应不会进入 Mova 的持久视频缓存；Windows 原生播放器也没有使用该设置预热下一集。自动跳过片尾并切集时，当前集仅按切换瞬间的位置保存，较长片尾可能让已经完成观看的剧集继续出现在“继续观看”中。

## 目标

- 接近片尾时把下一集的前 2 MB 写入现有持久缓存，并保留断点续传能力。
- 预热继续服从用户的缓存容量、网络类型和“预加载下一集”设置。
- 自动跳过片尾切集时明确把当前集记为已看完；手动切集仍保存真实进度。
- Windows 原生播放器自然播完一集时记录完成状态，手动上一集/下一集不误标完成。

## 非目标

- 本次不改变缓存目录、持久化键、服务器协议或默认设置。
- 不并行下载整集，不承诺切集时已经完整缓存。
- 不修改播放器控制条布局。

## 用户流程与界面

用户保持现有设置与播放流程。开启“预加载下一集”后，进入设定的片尾提前量时后台预热下一集；失败不阻断当前播放，切集后仍可正常从来源加载。自动片尾跳过会让已离开的剧集从继续观看中正确完成。

## 数据与接口

- 输入与输出：当前集位置、总时长、播放列表索引和下一集 URL。
- 数据来源：真实播放状态及现有媒体来源。
- 新增/修改字段：无持久化字段；缓存下载增加独立的单文件目标字节数。
- 持久化键或缓存格式：不变。
- 网络接口、超时与错误处理：复用 `VideoCacheStore`；预热失败静默降级为正常播放。
- 隐私与敏感信息：继续通过现有请求头与 URL 哈希处理，不记录凭据。

## 技术方案

- `VideoCacheStore.download` 分离“全局保留容量”和“本次下载目标”，预热只下载 2 MB，但仍按用户容量执行 LRU。
- Flutter 播放页用独立任务持有下一集预热，不覆盖当前集缓存进度；切集和退出时取消旧任务。
- 自动片尾切集向历史保存传入明确的 `isPlayed`，手动切换不传。
- Windows 原生层在 mpv 的 EOF 事件输出完成集索引，Dart 侧写入对应历史；并按用户设置在片尾窗口启动持久预热。

## 兼容与迁移

- 旧版本数据是否可继续读取：是，无格式变化。
- Windows / Android 差异：Windows 从原生 mpv 事件获取自然结束；Flutter 播放页从自动片尾动作获取完成语义。
- 回滚后是否安全：是，已预热的 `.part` 仍是旧版本可续传的缓存分片。
- 是否需要迁移、清理或功能开关：不需要，复用现有开关。

## 风险与回滚

- 主要风险：预热与当前播放争用有限带宽；因此目标固定为 2 MB，且只触发一次。
- 监测方式：缓存元数据、继续观看状态及 GitHub 双端构建。
- 回滚步骤：移除独立预热任务与 EOF 完成事件；缓存格式无需回滚。
