# 播放器完整剧集目录与弹幕上限

## 基本信息

- 标题：播放器展示完整季/集目录，弹幕最多加载 10000 条
- 日期：2026-09-28
- 状态：已完成
- 影响平台：两端
- 关联 Issue、提交或版本：无

## 背景与问题

播放器的剧集菜单由已聚合到可播放资源的集生成。详情页按用户约定只搜索选中集，导致播放器菜单遗漏尚未搜索的集。弹幕解析、缓存和 Windows 原生播放器的保护上限目前为每集 1000 条。

## 目标

- 根据 TMDB 季目录的集数展示完整季/集选择列表，并纳入实际资源/元数据中的额外集。
- 尚未搜索的集只作为目录项展示；用户选中时才按该集聚合服务器，找到资源后切换播放。
- 将弹幕解析、缓存读取/写入及原生加载的单集上限一致提升至 10000 条。

## 非目标

- 本次不预先聚合整部剧的所有集，不改变服务器匹配规则。
- 本次不改变播放进度、历史记录或弹幕缓存格式。

## 用户流程与界面

- 播放器季/集菜单展示目录中的全部集；没有播放资源的集标记为可选/待搜索。
- 选择待搜索集后，按该季/集聚合服务器；有资源则继续播放，无资源则保留当前播放并提示。
- 弹幕获取超过 10000 条时截取上限内的数据并按播放时刻排序。
- Windows 原生菜单和 Flutter 播放器列表保持相同行为。

## 数据与接口

- 输入与输出：TMDB `seasons[].episode_count`、已加载的集元数据、当前可播放资源；输出完整集目录与按选中集的聚合请求。
- 数据来源：TMDB 季目录及已配置媒体服务器。
- 新增/修改字段：`TmdbSeason.episodeCount`；播放器仅新增运行时目录项，不新增持久化字段。
- 持久化键或缓存格式：不变；旧弹幕缓存仍可读取，读取上限提高。
- 网络接口、超时与错误处理：沿用现有单集聚合与服务器错误反馈。
- 隐私与敏感信息：不变。

## 技术方案

- TMDB 季模型解析集数；播放器根据集数生成目录并合并已知集元数据和实际资源。
- Flutter 播放器对待搜索项目调用详情页的单集解析回调；Windows 原生菜单将待搜索的季/集交回 Flutter，由 Flutter 搜索后重新启动原生播放。
- 弹幕的 Dart 客户端、缓存及 Windows 原生限额统一为 10000。

## 兼容与迁移

- 旧版本数据是否可继续读取：可以；弹幕缓存结构不变。
- Windows / Android 差异：Windows 使用原生菜单并在选择待搜索集时回到 Dart 重建播放；Android 使用 Flutter 列表并原位调用单集解析。
- 回滚后是否安全：安全，无新持久化状态。
- 是否需要迁移、清理或功能开关：不需要。

## 风险与回滚

- 主要风险：极长剧集会让菜单目录变长；TMDB 若未返回 `episode_count`，仍由已知元数据和实际资源补充。
- 监测方式：检查目录条数、选择未搜索集后的聚合结果及播放器重启流程。
- 回滚步骤：撤回播放器目录/回调及上限常量修改，无需迁移本地数据。

## 实现记录

- `TmdbSeason` 增加可选 `episodeCount` 并用完整目录生成播放器选择项；加载新季后增量合并集名/实际资源。
- Android 集选择在播放器内按需聚合；Windows 原生菜单将未搜索集交回 Flutter，搜索成功后重建播放，失败则恢复原集。
- Dart/缓存上限继承 `DanmakuClient.maxComments=10000`，Windows 原生解析/加载上限同步调整到 10000。
