# 弹幕亚像素平滑与原生播放器缓存接线

## 问题

- Windows 原生弹幕已经按显示器节拍绘制，但横坐标最终用整像素取整；约 3.8px/帧时会形成 `4/4/3` 的周期步长，肉眼仍可见细微抖动。
- 持久化弹幕缓存只接入 Flutter 播放器；Windows 原生播放器每次打开仍重新匹配和下载，并在退出时删除临时传输文件。

## 方案

- 保留现有节拍器，为每条已栅格化文字生成 4 个水平亚像素相位，按实时浮点横坐标选择 0/0.25/0.5/0.75px 相位；目标位置仍由整数 AlphaBlend 快速合成。
- 动画帧在高精度节拍点直接提交到独立弹幕层，不再只投递低优先级 `WM_PAINT`；后者在消息繁忙时会造成 1/3 刷新拍交替。相位位图只调用一次 GDI+ 栅格化，其余三档由缓存像素线性移位生成，避免持续入场时占满帧预算。
- Windows 原生播放器复用 `DanmakuCache`。24 小时内命中缓存时直接生成原生传输文件，不发网络请求；未命中或过期时按原逻辑获取，成功后持久化。
- 缓存 JSON 新增可选 `source` 字段；旧缓存缺少该字段仍可读取，无需迁移。

## 验证

- 缓存序列化往返测试覆盖评论、匹配名、来源和旧格式兼容。
- 原生代码以 `/W4 /WX` 编译，并运行现有弹幕布局/节拍探针。
- Flutter 静态检查与相关测试通过；Windows 构建部署到 `D:\Mova\mova.exe`。

实测（170Hz 屏幕、136 条同时在屏）：帧间隔均值 11.74–11.79ms，稳态 96.7%
