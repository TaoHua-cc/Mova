# 追剧日历与服务器协议输入修复

## 基本信息

- 日期：2026-09-24
- 状态：已实现并部署 Windows 本地版本；服务器对话框窄窗手工检查受当前窗口操作拦截
- 影响平台：Windows 优先；共享 Dart 逻辑兼容 Android

## 背景与问题

Trakt 与 TMDB/TVmaze 可能为同一集使用不同季集编号，当前日历只按季集号去重，产生两张卡。TVmaze 时间查询在 IMDb 查不到时未尝试已有 TVDB 编号。TMDB 常只提供播出日期，不能伪造时刻。服务器对话框把协议选择与地址输入割裂，未带前缀的地址仅在单字段特殊情况才解析。

## 目标

- 同一真实集仅显示一张卡，优先保留来源提供的精确播出时刻。
- IMDb 查询失败时尝试 TVDB；来源确实没有具体时刻时清楚标注，而非猜测。
- 移除日历顶部常驻已弃剧条，仍保留可发现的恢复入口。
- 日历卡突出播出时刻、剧集、平台；服务器协议选择与地址输入形成同一操作，选定协议后允许直接输入域名/IP:端口。

## 非目标

- 不抓取未经稳定公开接口提供的站点页面，不凭剧名和周播规律推算具体时刻。
- 不改变来源凭据、观看记录或服务器协议格式。

## 用户流程与界面

日历日期轨下直接是当天更新；已弃剧在日历标题区通过恢复按钮打开，不占页面常驻空间。卡片显示可靠的具体时刻或“时刻未公布”，以及主要季集与平台信息。服务器添加/编辑时协议置于地址字段旁，输入不带前缀的主机名即可；粘贴完整 URL 会同步选中协议，多线路保留已输入的协议。

## 数据与接口

- Trakt 日历已有 `episode.number_abs` 可作为跨分季集的绝对集数；旧缓存无此字段时从明确的 `Episode N` / `第 N 集` 集标题恢复。
- 日历缓存事件新增可选绝对集数，旧 JSON 继续可读；刷新后自然重写，不需要破坏性迁移。
- TVmaze 仅用与 TMDB 提供的 IMDb/TVDB 外部编号匹配的节目，不以模糊剧名认定时刻；失败和旧缓存沿用现有回退机制。
- 服务器地址标准化后仍保存既有 `Uri` 格式；无新持久化键。

## 技术方案

在 Trakt 事件模型中保留绝对集数，把日历合并逻辑提取为可测纯函数；同一 TMDB 剧集 ID + 绝对集数优先去重，其次原季集号。合并时以有具体时刻的事件提供时间，但保留本地海报和已知中文标题。TVmaze 外部 ID 按 IMDb、TVDB 顺序尝试。服务器输入共用一个标准化函数用于主地址与备用地址。

## 兼容与迁移

旧日历缓存无绝对集数时仍可按已有季集号读取；可识别的集标题用于补齐去重。服务端 URL 与旧版格式一致，回滚安全。Windows 为本次手工验证目标；Android 共享数据逻辑需通过单元测试，未要求本次安装包。

## 风险与回滚

不同来源的绝对集数也可能有误，只有在同一 TMDB 剧集 ID 且明确集数时合并；无法确定的记录保留而不误删。新增字段可选；删除相关逻辑即可回滚。
