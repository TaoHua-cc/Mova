# Windows 原生播放器 seek 稳定性

## 基本信息

- 标题：Windows 原生播放器跳转进度稳定性
- 日期：2026-09-23
- 状态：实现中
- 影响平台：Windows

## 背景与问题

Windows 原生播放器在进度条跳转、快捷键快进/快退和片段跳转时，可能在新 Range 请求建立期间收到旧读取的错误结束事件。连续快进时恢复点也可能落后于用户最后选择的位置。

## 目标

- seek 恢复点与用户最新请求保持一致。
- seek 期间被替换的旧请求错误不应单独使播放进入失败态。
- 实际读取中断仍保留有界重试和明确错误提示。

## 非目标

- 不改变服务端 Range 协议或视频缓存格式。
- 不调整解码器、视频同步模式或画质设置。

## 技术方案

- 在 Windows 原生播放器集中处理绝对 seek 和相对 seek，统一记录目标位置。
- 相对 seek 基于最近 pending 目标累加；回退恢复以待跳目标为检查点。
- pending seek 有效期间忽略旧读取的 ERROR end-file，不误判整集结束。

## 兼容与迁移

- 不修改持久化数据或服务端协议。
- 仅影响 Windows 原生播放器；Android 继续使用 media_kit 的 seek 路径。

## 风险与回滚

- 若服务器本身不支持有效 Range，随机跳转仍可能失败；保持现有有限重试，不能无限重载。
- 回滚仅需撤回 `windows/native_player/main.cpp` 本次 seek 状态变更。

## 实现记录

- 统一记录绝对/相对 seek 目标，并在跳转期间将恢复检查点设到目标位置。
- 一度屏蔽所有待跳期间的 ERROR，发现这会连真实 seek Range 失败一起过滤、使自动恢复失效；已撤销此过滤。
- 现在仍对 seek Range 错误执行最多两次有界恢复，并仅去重重试 loadfile 期间旧文件迟到的 ERROR。
- 原生 Release 编译成功；本机未安装 Python，Range 注错自动探针无法运行。
- Flutter 测试运行器在此 Windows 环境启动挂起，自动化测试未能执行；原生播放器编译通过。
