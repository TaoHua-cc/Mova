# 播放与缓存共享取流及服务器代理路由

- 日期：2026-10-03
- 状态：已实现并本地部署，持续网速待对照复测
- 平台：Windows、Android

## 背景与目标

同一视频的后台缓存和本机播放代理各自请求源站；开放式 Range 不能复用增长中的缓存。Windows 视频流又无条件跟随系统代理，与服务器开关不符。

播放代理优先读取当前缓存下载已经落盘的数据；缓存增长时等待同一任务，不额外拉取同一段。请求超出窗口时由源站补齐剩余响应，不能把分片终点当成影片结束。视频下载、探测和代理统一按 sourceId 决定直连或系统代理。

## 数据与兼容

复用现有窗口文件、元数据和容量偏好，不修改持久化格式。sourceId 仅作为会话路由输入；无服务器标识的播放默认直连。保留缓存滚动、次集预热和播放完成删除。

## 风险

缓存读取与窗口替换并发；必须按最新文件区间读取，避免提前 EOF。异常下载不能无限等待。生产日志不得输出 URL、头部或凭据。视觉和性能效果需真实资源复测。

## 实现记录

播放代理读取下载任务的增长文件，窗口外仅补齐响应尾部；实际续播/跳转偏离下载位置时让同一个任务接续到播放请求位置。所有媒体 HTTP 客户端共用服务器代理开关，无 sourceId 默认直连。持久化格式不变。

验证：完整 Flutter 测试 336 项通过，其中新增 5 项覆盖增长文件、窗口边界、取消、源站忽略 Range、实际跳转优先。静态检查 21 项既有 info，无 error/warning。Windows release 已覆盖 D:\Mova，部署 app.so 与构建哈希一致；Android arm64 release 构建成功并通过 adb install -r 安装到 OPPO 平板，保留数据。

实播《兰香如故》第一季第二集：Mova 当前建立服务器 443 直连与本机播放器连接，没有系统代理 7897 连接。此证据验证当前路由，不代表持续速度已经提高。Android 实播、开启代理服务器及持续速度仍需人工对照。源站不支持 Range 时，为取得尾部仍需重读并跳过前缀，这是源站能力限制。

## 安卓缓冲不足诊断（后续）

### HTTP 原生取流兼容修复

原生 Exo 切换 HTTP 服务器后实播报 CleartextNotPermittedException；之前只连接本机代理，掩盖了系统配置不允许任意 HTTP 地址的问题。用户授权修复：网络安全配置 base-config 允许 HTTP，保留现有 system/user trust anchors 和 HTTPS 标准证书校验。不硬编码用户 IP，不修改服务器 URL，不将 HTTPS 降级。移除误将 IP 视为网段的 domain 白名单；静态 XML 无法为用户动态添加的服务器维护域名列表。风险：此许可是应用范围，HTTP 请求/重定向均可能明文传输，推荐服务器提供 HTTPS；已有内置服务 HTTPS URL 不变。仅安卓配置，无持久化迁移，Windows 不变。验证配置回归、XML 解析、安卓 release 构建安装及同一失败资源真机复测。

### 原生取流正式落地范围

### 双端每秒缓冲读取速度

用户要求每秒更新真实缓冲读取速度、停止读取显示 0 KB/s。Exo 沿用 Media3 字节统计；Windows 与安卓 mpv 使用播放代理交付字节计数，不再使用独立后台下载进度或缓存速率估算。原生 Windows 每秒通过现有 stdin MOVA_NETWORK 通道接收统计，退出取消计时器；切集重新基线，无倒退负值。代理分别统计增长文件、缺失尾部及完整源站响应，后台下载不计入。数据为当前播放的实际交付量（包括媒体索引读取），不是系统网络带宽；无代理的完整本地文件不计网络读取。计数仅会话内存，不更改持久化格式。双端本地部署，未要求发版。

验证：339 项完整测试通过，包含每秒接线和交付字节等于响应长度检查；计数在 add 成功后、flush 等待前更新，避免客户端已读完而计数还未更新的竞态。静态检查无 error/warning，仅原有 info。Windows release 编译及覆盖部署完成，app.so 和 MovaNativePlayer.exe 与构建哈希一致；Android arm64 release 编译、adb 保留数据安装成功。真实播放的每秒显示、停读归零与切集需用户后续复核，未推送/发版。

用户授权采用 Exo 原生取流及实测读取速度。未勾选代理服务器的 Exo 默认直接读取源站并保留鉴权头；已有完整 Dart 视频缓存继续可播放，不清理旧缓存。该路径禁用独立当前集/次集后台下载，避免重复拉取。勾选代理的服务器继续本机代理以遵守其路由，mpv、Windows 不改变。Media3 TransferListener 用线程安全字节计数，每秒计算读取速度并通过现有状态事件传给 Dart；缓冲满停止读时归零，不伪造带宽。诊断编译开关不再决定路径，仅可开启日志。原生持久缓存需要单独接入，本次不引入第二套格式或迁移。验收：默认路径、代理保留、鉴权、旧完整缓存和实测速度接线测试，静态检查、安卓构建部署及真机复测。

落地验证：338 项完整测试通过，静态检查无 error/warning（21 项原有 info）；Android arm64 release 不带诊断 define 构建成功，adb 保留数据覆盖安装成功。原生直连对照实际前 5 秒接收 53363642 字节，约 10.2 MiB/s，随后约 50 秒前向缓冲、采样期间无再次 buffering；这是读取吞吐，缓冲满后的低速不是可用链路带宽。正式包界面每秒实测速度、已缓存文件、勾选代理以及 mpv 回退需要后续人工复核。Windows 未部署；未推送或发布。

用户关闭 Clash VPN 后仍卡顿。Exo 日志捕获前向缓存 746 ms 时进入 buffering，约 4 秒后以 2846 ms 前向缓存恢复。系统 socket 接收队列有数 MB 积压，但无进程归属证明，不能据此判定源站速度或应用故障位置。

增加仅 `MOVA_TRANSFER_TRACE=true` 构建启用的数值日志，默认关闭、不新增偏好或缓存格式。每个活动取流最多每 5 秒报告一次累计字节/耗时：originCache（接收并入写队列的字节、文件实际长度）、cacheProxy（文件读取时间、响应 flush 时间、等待缓存时间）、originTail 和 originProxy（对应直接源站响应）。不记录 URL、凭据、影片名或缓存键；不中途 flush 写入器，保持取流行为。计数表示各段吞吐，不能直接当成链路带宽。

开启诊断的 5 项取流集成测试通过，静态检查无 error/warning。仅构建部署安卓诊断包，Windows 保留上一版。实际卡顿原因待同资源采样确认，诊断包不是性能修复。

采样发现：cacheProxy 20 秒交付 22220269 字节，文件读取流程累计 18969004 微秒，发送 flush 累计 22840 微秒；originCache 接收 23350764 字节，落盘 23346669 字节。文件读取流程是明显瓶颈，不能将累计读取耗时直接解释为磁盘硬件带宽。安卓改为同一响应复用读取句柄，在任务、窗口起点或文件路径变化时重开，并保持读后窗口一致性校验和 finally 关闭。Windows 有打开文件阻止改名的行为，继续逐块关闭（按实际 Platform.isWindows 判定，而非测试 UI 平台）。5 项回归通过。实际平板改善幅度待复测。

句柄复用后用户仍卡顿：cacheProxy 30 秒读取耗时约 27.16 秒，改善不足。启动时出现 originProxy 与 originCache 并行；尾部索引请求会优先重定向缓存任务到片尾。进一步限制重定向为开放式且距离片尾超过 1 MiB 的请求，短片尾索引请求走独立补取而不抢占预读；任务还在重建窗口且 totalBytes 为 0 时等待元数据完成，不立即回退源站。安卓增长文件读取在不足 256 KiB 时合并等待，最多增加 200 ms，再按实际可读量交付；短响应、完成/取消任务不等待。诊断增加实际 read 次数。新增尾部索引不改变下载起点测试，6 项取流测试通过，静态检查无 error/warning。尾部 1 MiB 内真实拖动仍可回退取流，但不触发后台任务重定向（保守避免索引抢占）；改善待真机验证。

第二轮复测仍勉强：70 秒 cacheProxy 交付约 77.75 MB，累计读取约 14.04 秒；originCache 68.5 秒接收约 77.87 MB，读写基本同步，但不证明源站带宽上限（流控及调度仍会影响）。用户授权 Exo 原生取流对照。增加默认关闭、无持久化的 `MOVA_EXO_DIRECT_PROBE` 构建开关：仅 Exo 且未勾选服务器代理时绕过 Dart 本机代理、完整本地缓存和当前/次集视频下载，保留鉴权头、进度、UI与其他数据功能。勾选代理的服务器仍走原路径；本次要求 VPN 保持关闭以控制变量。Media3 TransferListener 每 5 秒输出纯数值实际读取量与耗时，ticker 同频记录前向缓冲，不输出 URL、头或媒体身份。不改变 LoadControl 参数。13 项相关测试通过，静态检查无 error/warning，安卓原生构建和部署后真机结果待确认；Windows 不更新。
