# 弹幕匹配失败恢复

## 基本信息

- 标题：弹幕匹配失败原因与重新获取
- 日期：2026-09-23
- 状态：已完成（待实机验证）
- 影响平台：Windows / Android

## 背景与问题

弹幕服务的匹配、网络请求或返回空数据时，界面可能只显示笼统的失败/无数据；播放期间缺少直接重试入口。Windows 获取器逐个尝试来源，但丢弃了具体 API 错误；每源可等待 12 秒，外层却固定 20 秒，多个来源时可能提前取消。

## 目标

- 保留失败来源的具体错误，区分网络/API 错误与未匹配/空结果。
- 播放中能手动重新匹配并获取当前集弹幕。
- 重试忽略正向缓存；失败结果不写入缓存，成功非空结果继续复用缓存。

## 技术方案

- 复用 `DanmakuClient`、`DanmakuCache` 和现有 generation 防过期机制。
- Android 面板添加重新获取动作。
- Windows 原生弹幕面板通过 stdin/stdout 发起当前集强制刷新。

## 兼容与迁移

- 缓存格式及 SharedPreferences 键不变。
- 不新增依赖；Windows 使用原生播放器与应用进程现有通信。

## 验收标准

- [x] 弹幕错误或无结果时显示重新获取动作。
- [x] 重试真实调用 API，不被新鲜缓存短路。
- [x] 换集期间旧请求不能覆盖新集数据（复用现有 generation 检查）。
- [x] 网络失败后可再次重试，成功后正确加载。

## 验证计划

- [ ] 针对性 Flutter 测试
- [x] Windows Release 构建
- [ ] 人工验证 API 可用、API 不可达和无匹配三个结果

## 实现记录

- Windows/Android 播放面板提供“重新获取弹幕”，请求时显示加载状态，重复点击禁用。
- Windows 原生面板接入应用进程刷新命令；强制刷新跳过缓存，失败不写缓存。
- Windows API 全部失败时保留最后一个可读错误，而非统一显示“没有匹配的弹幕”。
- Windows 总超时按 API 数量计算为每源 12 秒加 2 秒余量，避免固定 20 秒提前取消后续来源。
- Windows Release 构建成功并部署；针对性 Flutter 测试未运行（执行策略拒绝），实际 API 的成功/失败/无匹配路径待实机验证。
