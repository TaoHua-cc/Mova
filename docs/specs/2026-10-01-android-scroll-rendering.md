# Android 平板滚动渲染复查

## 基本信息

- 日期：2026-10-01
- 状态：已部署测试版；用户确认优化有效，连续滚动达标，切页仍有尖峰
- 影响平台：Android；Windows 保持原稳定玻璃行为

## 背景

Android 应用外壳和多个主页面滚动容器都处于 `YingjiStableScrollGlass` 范围。玻璃组件因此持续执行背板采样，即使平板正在滚动。既有同设备 FrameTiming 记录显示，玻璃旁路时 Raster P50 从约 20–52ms 降至 6.7–12.6ms；“全部列表”则以懒构建海报网格为主，渲染成本显著更低。

## 目标与方案

- Android 主页面和共享滚动容器在滚动期间暂停玻璃背板采样，静止后恢复。
- Android 主页面切换直接落位，避免同时合成两个复杂页面；Windows 保留相邻页面动画。
- Android 切页首帧短暂暂停动态背板采样，保留材质底色/形状，再恢复玻璃滤镜。
- Android 关闭 `PageView` 相邻页面预构建；导航使用点击切页，不需要预先构建日历/设置等非当前整页。桌面行为不变。
- Windows 滚动期间继续维持稳定玻璃。
- 明确包裹的弹出菜单/对话框不随本次修改改变。
- 在同一台 OPD2401 平板的 Release 测试包上，以 Flutter FrameTiming 对比卡顿页面和发现“全部列表”；最终再安装关闭诊断的测试包。

## 验收

- [ ] Android 共享滚动容器不再建立稳定玻璃范围。
- [ ] Windows 继续建立稳定玻璃范围。
- [ ] 对话框仍保留稳定模糊。
- [ ] 测试/静态检查通过。
- [x] 平板发现页连续触控滚动：单秒窗口 127 帧，Raster P50/P95=4.73/6.82ms。
- [x] 同机设置页/日历页已加载后重复切换：Raster P50=13.28ms、P95=56.15ms；Build P50/P95=14.30/32.37ms。仍有超过 20ms 的切页慢帧，不能据此声称整个软件已完全流畅。
- [x] Android 空闲显示模式为 50Hz，设备支持最高 144Hz；触控滚动时 FrameTiming 约 127fps。帧预算字段反映采样时系统报告的 50Hz，不可将其当成触摸期间固定刷新率。
- [x] 最终关闭帧日志的本地 Release 测试包已安装到 `com.taohua.mova.debug`。

## 实现记录

首轮 FrameTiming 实测确认滚动中位 Raster 由约 19ms 降到约 5ms；直接切页仍有 35–128ms 慢帧。全玻璃旁路后同一切页 Raster 中位数降至约 6–18ms，证实大面积背板采样是切页光栅热点，但页面构建也造成尖峰。因此增加 Android 直接切页、首帧短暂暂停采样，并关闭不必要的邻页预构建。最新设备数据表明连续滚动已明显改善，但页面切换 P95 仍超过 50ms；需继续关注路由内容构建和恢复玻璃滤镜后的尖峰，不宣称所有交互已完全流畅。

用户确认当前平板滚动修复“有效果”。本轮确认了主要原因与边界：触控滚动时暂停大面积背板采样后，首页滚动测到约 127 帧/秒、Raster P50/P95 4.73/6.82ms；切页仍存在 Build/Raster 慢帧，因此效果有效但不是全局无卡顿。
