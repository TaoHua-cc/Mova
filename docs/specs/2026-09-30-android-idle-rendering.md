# Android 全局渲染卡顿修复

- 日期：2026-09-30
- 状态：已实现
- 平台：Android；Windows 回归

## 问题与证据

OPD2401 平板，Android Debug 测试版仍连续出帧，SurfaceFlinger 记录 1711 帧、平均 47.170 FPS；采样后截图确认当前为发现列表（此前空服务器页也测到持续出帧）。共享背景两层 1.8 × 1.4 视口渐变由 28 秒循环动画持续平移，真实玻璃采样无法静止复用；Debug 构建额外增加开销。不能以此断言视频解码帧率。

## 方案与流程

Android 保持现有渐变配色与玻璃材质，静止背景不注册连续动画。Windows 保留漂移动画，但遵守减少动画、TickerMode 与滚动冻结。壳层不可见页关闭 TickerMode，首页轮播 Timer 不再推进隐藏页面或被详情遮挡的页面。没有数据或协议变更。

首页每 100ms 更新且动画持续 120ms 的轮播圆点独立 RepaintBoundary，避免逐帧带动其他卡片/玻璃重绘；海报转场清晰后关闭零模糊 ImageFiltered 离屏层，不取消真实切换动效。

## 构建兼容

新增仅显式 Gradle 属性 `movaLocalTest=true` 的本地 Release 测试构建，包名使用现有 `.debug` 测试包、标签为 Mova · 测试，强制调试签名；默认正式构建不变，不覆盖用户正式版、不发布。用于排除 Debug / JIT 性能开销。

## 验收与验证

- Widget 测试 Android 背景空闲不持续调度帧；Windows 正常动画且关闭后无残留 ticker。
- Android 材质模糊仍受原有外观设置控制，不全局删除玻璃。
- 格式化、静态分析、相关测试、双端构建与本地部署。
- 同设备同页面检查静止持续出帧与 CPU，明确静止低 FPS 是不再绘制，不是丢帧。
- 无实际片源配置时不声称视频/带数据列表已验证。

## 风险与回滚

Android 背景不再漂移为有意视觉调整；Windows 原有效果保留。删除平台冻结逻辑可回滚，无数据迁移。

## 实现与验证结果

- 新增 3 项回归测试：Android 空闲且保留玻璃、Windows TickerMode、首页局部重绘/隐藏轮播；与引擎和玻璃测试合计 6 项通过。
- 最终静态检查无 error / warning，保留仓库既存 info；发现滚动测试 8 项通过、1 项旧断言失败（要求 brand.dart 包含已不存在的 BackdropFilter.grouped），未改无关断言掩盖问题。
- Android AOT 测试版已成功覆盖 `.debug` 包，用户已配置的服务器和记录保留；正式包不变。Windows Release 已构建部署。
- 真机服务器页（实际已连接一个来源），用户停止操作后采样约 30 秒：没有应用 SurfaceView 持续出帧；系统状态栏约 1 FPS 更新属正常。top 瞬时 CPU 从采样开始 3.5% 到结束 0.0%。这证明空闲连续渲染停止，不表示实际交互无限 FPS，也不作为 Debug → Release 的纯单因素百分比性能提升。
- 修复前 Debug 发现列表 top 瞬时 CPU 122%，不同页面与构建类型不可直接算提升比例。视频播放及复杂弹层仍需按真实使用继续复核。
