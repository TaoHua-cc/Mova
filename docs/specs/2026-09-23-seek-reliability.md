# 网络流跳转可靠性

## 问题

Windows 原生播放器拖动进度条时按每个鼠标移动事件调用 mpv seek，网络流会连续重建
Range 请求；服务器或代理偶发中断后，重试又使用旧播放位置。

## 修复

- 拖动期间只更新进度预览，鼠标松开时仅提交一次绝对时间跳转。
- 普通进度跳转最多到总时长前一秒，避免误触发播放完成。
- 暂存跳转目标；新位置尚未回报就中断时，重开后优先恢复到该目标。
- mpv 回报已抵达目标附近后清除暂存值。
- Windows 网络播放明确启用缓存暂停保护，跳转后的新 Range 请求积累到可稳定播放
  的数据量后再继续画面。
- 跳转尚未抵达目标时允许两次有界恢复；普通播放仍只重试一次，坏源不会无限循环。
- 弹幕跳转仅撤下在屏条目，向后跳时只复位实际跨过的区间，不再扫描整集并销毁
  与播放位置无关的文字纹理。

## 验收

- 一次拖动只产生一次 seek 命令。
- 跳转期间发生可恢复断流时仍从目标位置继续。
- 拖到进度条最右端不会被普通 seek 误判为自然播放完成。
- 跳转后弹幕无需全量重新栅格化，画面与弹幕在缓冲期间同步停住、恢复后同步继续。
