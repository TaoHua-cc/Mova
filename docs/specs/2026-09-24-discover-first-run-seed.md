# 首次启动发现页预置数据

## 基本信息

- 标题：首次启动显示默认发现栏目、海报快照并后台更新
- 日期：2026-09-24
- 状态：实现中
- 影响平台：Windows / Android
- 关联 Issue、提交或版本：无

## 背景与问题

新安装没有发现页偏好与榜单缓存，首次启动要等待联网后才有栏目内容。当前维护机已有一套用户认可的 18 个发现栏目顺序、卡片样式、数据源与公开 TMDB 榜单缓存。应用另有大容量本机图像、观看记录、视频与弹幕缓存，不能整体作为默认数据发布。

## 目标

- 新用户首次打开时先显示维护机的 18 个公开发现栏目布局与列表快照，再由现有 TMDB 缓存优先/后台刷新机制更新。
- 首次布局采用本机已选顺序、样式、数据源和可共享的榜单筛选项。
- 发现页每个横向栏目最多预览 20 个项目；进入完整列表后仍可继续分页。
- 选中控件恢复为 Mova 珍珠白玻璃与深色前景，不使用棕色强调色。

## 非目标

- 不迁移、覆盖已安装用户已有栏目、排序、筛选或网络设置。
- 不打包账号、API 密钥、Trakt、服务器配置、观看记录、片单、视频/弹幕缓存或整个图片缓存目录。
- 不带入完整本机图片缓存；仅为当前 18 个第一页快照携带已缓存的小尺寸 TMDB 海报文件，其余缺图仍使用现有网络图片路径。

## 用户流程与界面

新安装启动后先载入内置栏目配置与真实 TMDB 列表快照，海报记录与已有占位/图片缓存路径正常渲染；随后后台请求新结果并仅在数据变化时替换。栏目横向预览上限为 20 个项目，点击“打开完整列表”继续加载其他页。宽屏与窄屏使用同一数据规则；鼠标、键盘和触控入口不变。

选中按钮、筛选标签、切换项及卡片的选中色统一使用珍珠白玻璃与深色图标/文字。

## 数据与接口

- 输入与输出：只读导出维护机 `yingji.discover.*` 布局偏好、8 个公开列表筛选偏好及对应的第一页 TMDB 列表缓存，生成只含必要字段的内置快照与缓存海报。
- 数据来源：本机 `shared_preferences.json` 中的公开发现栏目偏好与托管 TMDB 列表响应。
- 新增/修改字段：无持久化格式变化；仅添加内置 JSON 资源和首次启动播种标记/逻辑。
- 网络接口、超时与错误处理：继续复用当前缓存优先及后台刷新路径；后台失败时继续展示快照。
- 隐私与敏感信息：筛选与缓存导出必须拒绝包含账号令牌、服务器地址、个人 API key 的条目；不得复制本机完整 SharedPreferences、媒体/弹幕缓存或图片缓存。

## 技术方案

- 将 18 栏本机顺序、每栏卡片样式与公开 TMDB 数据源作为项目默认值。
- 为首次启动提供经过白名单筛选的列表快照；仅在没有用户保存布局时应用，不覆盖现有偏好。
- 通过纯函数限制发现横向栏目的项目数为 20；完整列表仍使用当前分页加载路径。
- 复用 `YingjiGlass.accent` 珍珠白令牌与既有玻璃高光，不另建主题系统。

## 兼容与迁移

- 旧版本数据是否可继续读取：是，旧 SharedPreferences 键保持原样。
- Windows / Android 差异：共享 Flutter 层使用同一内置快照；平台图片缓存位置不同但不影响列表快照。
- 回滚后是否安全：是，新增播种标记与资源不会破坏旧偏好；移除新版本后旧行为继续读取同一偏好。
- 是否需要迁移、清理或功能开关：无需迁移；播种只针对缺少布局偏好的新安装。

## 风险与回滚

- 主要风险：静态榜单快照会随时间变旧；后台刷新须在首屏完成后及时启动。
- 监测方式：测试播种与刷新顺序，人工验证新装冷启动。
- 回滚步骤：移除播种资源与首次运行逻辑；保留用户已产生的 SharedPreferences。
