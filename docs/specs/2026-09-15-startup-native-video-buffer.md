# 启动动效、Windows 原生画面与缓存进度修复

## 基本信息

- 标题：启动动效、Windows 原生画面与缓存进度修复
- 日期：2026-09-15
- 状态：已完成并发布 v3.1.104
- 影响平台：Windows / Android
- 关联 Issue、提交或版本：v3.1.103 后续开发

## 背景与问题

当前启动画面只有简单缩放和线性等待条，品牌表现较弱。Windows 原生视频宿主把 64 位 HWND 截断为 32 位后交给 libmpv，导致音频正常但 gpu-next 没有有效画面目标。播放器虽读取 mpv 缓冲终点，却没有规范化异常值，也无法表达整片已落到本地缓存的状态。

## 目标

- 启动画面采用克制、电影感的 Mova 品牌动效，不显示虚假百分比。
- Windows 将完整 HWND 传给同一个 libmpv/gpu-next 播放器并恢复画面。
- 时间轴清晰区分已播放、已缓冲和未加载范围；缓存终点不早于当前播放位置，完整本地缓存显示到片尾。

## 非目标

- 本次不新增第二播放器，不实现 Dolby Vision 授权直通。
- Windows 点击播放后直接启动随应用分发的 `MovaNativePlayer.exe`，该程序动态
  加载 `libmpv-2.dll` 并使用 gpu-next/libplacebo；不再分发或启动独立
  `mpv.exe`，也不使用 Lua OSC。视频和自绘控件属于同一个 Win32 播放器进程；
  Android 继续使用 Flutter PlayerPage。
- 视频缓存档位表示持久化前向预读容量，而不是允许缓存的最大整片大小；通过
  本机 HTTP Range 代理复用已有分片，缓存范围内的续播与跳转不重复下载。

## 用户流程与界面

冷启动显示深色电影画布、柔和光晕、轨道线和品牌标识，真实初始化结束后淡入首页。播放器进度条以白色表示已播放、半透明亮色表示已缓冲、暗色表示尚未加载。宽屏和窄屏沿用现有布局与操作。

## 数据与接口

- 输入与输出：原生进程通过 stdout 回传播放位置、时长和选集索引；Flutter
  通过 stdin 向原生进程发送持久缓存字节进度。
- 数据来源：当前 Player 状态和本机视频缓存命中状态。
- 新增/修改字段：仅增加页面内存状态，不修改持久化格式。
- 持久化键或缓存格式：不变。
- 网络接口、超时与错误处理：不变。
- 隐私与敏感信息：不涉及。

## 技术方案

- `startup.dart` 复用品牌色和现有 logo，以单个动画控制器驱动光晕、轨道及加载光点。
- `windows/native_player/main.cpp` 创建独立 Win32 播放窗口，在初始化 libmpv 前
  设置完整 64 位 HWND，并用 GDI+ 双缓冲绘制顶部栏、控制条和选择浮层。
- 提取纯函数规范化缓存终点并添加单元测试；本地完整缓存直接标记为总时长。

## 风险与回滚

- 主要风险：原生控件仍基于 GDI+，后续可迁移 Direct2D/DirectComposition 进一步
  改善亚像素文字、模糊材质和高帧率动画；DV 最终输出仍受显卡、驱动和显示器能力影响。
- 监测方式：播放器诊断、Windows 实机样片、窗口缩放测试。
- 回滚步骤：回退本规格对应提交；缓存数据无需清理。

## 实现记录

- Win32 与 Dart 两端移除 HWND 的 32 位截断；Flutter 传入的视图坐标直接用于同一父窗口的 WS_CHILD，避免再次转换后把视频移到负坐标；Windows release C++ 编译通过。
- 启动页改为径向电影画布、旋转轨道、呼吸式品牌卡与无百分比光带。
- 时间轴规范化 mpv 缓冲终点，并对完整本地缓存显示全片可用。
- 本地安装包 `Mova-3.1.103-local-Windows-x64-Setup.exe` 已覆盖安装到 `D:\Mova`；可执行文件、`data/app.so` 与 libmpv 的 SHA-256 均和本次构建一致。
- Windows 已重构为单一原生播放器，支持持久缓存进度、进度拖动、音量、音轨、
  字幕、外部字幕拖放、倍速、比例、选集、上下集、历史记录和沉浸式窗口控件。
- 发布版本为 v3.1.104；后续接续说明见 `docs/HANDOFF.md`。
