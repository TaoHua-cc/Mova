# 继续播放移除状态

## 基本信息

- 标题：继续播放移除状态
- 日期：2026-09-29
- 状态：已完成
- 影响平台：两端
- 关联 Issue、提交或版本：用户反馈“继续播放的移除无法生效”

## 背景与问题

继续播放卡片是观看记录的投影。同一剧集组可能有多条历史记录，移除最新一条后，旧记录仍会成为卡片；服务器合并也可能重新导入已移除的进度。

## 目标

- 从继续播放移除后，整组内容在本机继续播放列表中保持隐藏。
- 保留底层观看历史和服务器数据，不把隐藏误做成删除或标记已播放。
- 用户再次播放并保存进度后，重新显示该组。

## 非目标

- 不删除媒体服务器或 Trakt 上的播放记录。
- 不改变播放进度合并规则及继续播放分组规则。

## 用户流程与界面

通过继续播放卡片的移除按钮或右键/长按菜单移除；首页和完整继续播放列表立即隐藏该组。再次播放该组内容并产生本机进度后恢复显示。Windows 鼠标与 Android 触控继续使用各自现有入口。

## 数据与接口

- 输入与输出：待隐藏的 `WatchState`；输出本机隐藏的分组身份集合。
- 数据来源：本机观看状态及服务器合并结果。
- 新增/修改字段：无。
- 持久化键或缓存格式：新增 SharedPreferences 字符串列表键，默认空；存继续播放分组别名，不修改旧观看记录。
- 网络接口、超时与错误处理：无新增请求；合并服务器记录时仍保留底层状态，仅从展示投影中过滤隐藏分组。
- 隐私与敏感信息：只存已有记录身份，不存凭据。

## 技术方案

在 `WatchStateStore` 复用继续播放已有分组别名，为隐藏/恢复提供本机状态；首页与完整列表共用过滤，新的本机播放保存清除对应别名。

## 兼容与迁移

- 旧版本数据是否可继续读取：可，新增键不存在时视为空集合。
- Windows / Android 差异：共享 Dart 逻辑，无差异。
- 回滚后是否安全：可，旧版本忽略新增键，旧观看记录未删除。
- 是否需要迁移、清理或功能开关：无。

## 风险与回滚

- 主要风险：隐藏状态按现有分组别名作用于整部剧，而非单一集。
- 监测方式：用多集同剧记录和服务器重复导入覆盖自动测试。
- 回滚步骤：回滚代码即可；旧逻辑忽略新键，必要时可在设置清空观看记录。

## 实现记录

已在 `WatchStateStore` 持久化继续播放分组隐藏别名，并让首页、完整列表和服务器合并共用过滤投影。首页移除回调直接更新当前卡片；同步返回和封面异步回调在发布状态前再次过滤，避免旧快照把卡片加回来；并发刷新会排队重试。隐藏时保留观看历史；后续新播放保存非完成进度时清除该组隐藏标记。自动测试覆盖多集同剧、陈旧快照、模拟服务器重新导入、跨 Store 实例持久化及播放后恢复。Windows Release 构建成功并部署到 `D:\Mova`，部署文件与构建产物 SHA-256 一致。
