# Android 服务器卡片紧凑布局

日期：2026-10-02。仅 Android 视觉变化；不改版本、数据、权限或持久化。

原因：此前 Windows 横向铺满规则位于共享页面，列数按服务器总数限制后均分可用宽度，Android 数量少时也被拉宽。

复用 YingjiLayout 布局令牌和现有卡片：Android 目标/最大宽度340逻辑像素，间距12；以340计算列数后限制卡片最大宽度，数量少也不拉伸，多余项正常换行，窄屏使用实际可用宽度。Windows 保留388列宽基准及整行均分。保留卡片内容、144最小高度、字号及触控目标，避免为了变小重新裁掉主线路延迟。没有创建另一套材质。

自动检查：布局函数覆盖可用宽度240/600/900/1400及服务器数量1/2/5/20；Windows 单服务器900、两服务器444及自动换行规则保持。针对性14项测试通过。宽窄屏横竖向真实卡片布局仍需人工复核，未做设备截图验收；无数据时仍使用原可信空态。回滚仅恢复页面宽度计算，不涉及数据迁移。

交付：完整304项测试通过，静态分析无错误/警告（19项既有info），Android测试版Release构建及平板“Mova · 测试”覆盖安装成功（2026-10-02 02:39:35）。Windows仅通过布局函数回归测试验证旧规则，本次不构建/部署Windows，不提交或发版。
