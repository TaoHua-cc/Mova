# Windows 下一集正式会话预备

- 日期：2026-10-10；状态：已实现、受控测试通过，Windows 已部署；真实服务器验收待完成；范围：Windows。
- 原故障：独立 32 MiB 文件预热在切集后通过缓存桥补流，重复 403；原生恢复同样被拒绝。
- 用户确认目标：下一集已经是正式播放会话，只保持暂停、零进度并原生预读；切集接管该会话，不重新 loadfile，不从文件缓存拼接后续数据。

## 技术方案与验收

- 先验证安装的 libmpv 在暂停状态能真实预读，以及输出接管不会重开流；验证不过不部署宣称完成的版本。
- 最多一个下一集会话、独立鉴权，保留 80%/缓冲到片尾触发与预读秒数设置；当前集缓冲不足时停止预备。预备没有观看记录和服务器播放回传。
- 取消切集、切资源、关预加载或退出及时释放会话；同一原生窗口输出接管，事件只归属于当前活动会话，旧会话不得串入新集。
- 不新增外部播放器进程，不关闭 TLS，不绕过服务器代理。不保证断网/持续鉴权拒绝时零停顿。
- 受控测试必须覆盖暂停进度不推进、缓冲增长、同会话恢复、无第二次打开、失败隔离、资源释放；随后构建 Windows、实际自动切集和至少 60 分钟长测。
- Android 保持原实现，不部署。版本不变，不提交、推送或发布；当前诊断与恢复改动保留，旧缓存格式不迁移。

## 风险与回滚

双会话会增加解码/渲染资源占用。必须验证暂停会话输出如何切换，不能将独立预下载冒充正式会话。可撤销本次原生会话相关改动回滚；用户历史与旧缓存不删除。
